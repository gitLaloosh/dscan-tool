Last Kill hull pivot button

Date: 2026-10-10   Status: Delivered, verified via 28/28 regression PASS + a 7/7 real-Chromium Playwright test driving the actual click interaction end-to-end

Requested by Erik: "a button that modifies the pilot analyzer search as if you searched for the ship that they last recorded a kill in... should be displayed in a way that makes sense if the user sees what they used in their last kill and decides they'd like to see their most recent losses for that hull." Confirmed the Pilot Analyzer's existing "Last Kill" section (what hull a pilot was flying when they killed someone, separate data from their own losses) was the right anchor point for this.

The change

The Last Kill section already resolves and displays the hull a pilot was flying on their most recent kill (attacker.ship_type_id/flownName inside renderLastKill()). Added a button right there -- "See <pilot>'s recent losses flying a <hull>" -- that, on click, re-runs the exact same runFitForShip() path the manual ship-name box and the "most flown" candidate buttons already use, targeting that specific hull. It also writes the hull's name into the manual-ship input box, so the visible search state matches what actually ran (this matters for the existing "Refresh losses" button, which just re-invokes whatever search last ran), and clears any stale "most flown" candidate buttons left over from a prior speculative search. No new network calls or data -- this reuses a value (attacker.ship_type_id) the Last Kill section was already fetching and displaying, just not acting on.
