Bug found and fixed: scripted Heavy Interdictor bubbles

Since v2026.10.14.26 the engine paired a Warp Disrupt Field Generator's script from mid-slot flags only. A WDFG is a high-slot module, so on a real killmail or EFT paste the tool missed the script. On a scripted HIC it then:

  • added the bubble's +50% signature bloom, which pyfa leaves out when a charge is loaded (Effect3380);
  • kept the unscripted cycle and capacitor need: 30 s and 112.5 GJ instead of the Focused script's 6 s and 45 GJ.

The v.26 test fits listed the WDFG as a mid slot, so the code and the test fits agreed (LESSON #37). The fix also pairs high-slot scripts for WDFGs. Only WDFGs: a turret's crystal in the same high-slot flag is handled by the weapon capacitor path. On the new HIC golden fit: signature 225 → 150 m, capacitor stable 81.2% → 69.2%, both equal to pyfa's handlers. v2026.10.14.34 fails compare_fit_stats.py on it.

Lesson for future models

  • Put every item in a constructed test fit where a real fit has it: a module in its own slot, its charge in that slot's flag. If code and fixture share a wrong assumption, they agree, and so does every check built on them. Build constructed fits from an EFT paste or a real killmail layout when unsure (LESSON #37).
  • A mutation that passes is a hole in the grid, not proof the code is right. Ask where the mutated rule changes the result, here a 150 m window around a drone's optimal, and put a point there.
  • When porting a function that reads src.item.extraAttributes[...], check where the tool keeps that value before reading it. A missing field reads as undefined, and distance <= undefined is silently false.
