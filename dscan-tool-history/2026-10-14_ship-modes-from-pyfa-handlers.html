Ship modes from pyfa's handlers (Anhinga, Skua, every mode stat)

Bug fixPYFA COREUITooling 2026-10-14 · v2026.10.14.5 → v2026.10.14.6 · Erik: "ok continue" (backlog item Modes); default Anhinga mode: "Primary (pyfa's default)"

Problem

pyfa gives every Tactical Destroyer and the Anhinga a mode (Ship.__getModeItems), and runs that mode item's effects like any other carrier. The tool had five hand tables (TACTICAL_DESTROYER_MODE_BONUS, _DEFENSE_SIG, _SHARPSHOOTER_SENSOR_MULT, _PROPULSION_BONUS, _SHARPSHOOTER_RANGE) covering four hulls. As a result:

  • The Anhinga had no mode at all. Its default Primary Mode cuts launcher cycle time to 0.75 (33 → 43 DPS), multiplies cruise missile flight time by 11 and targeting range by 5.
  • The Skua (a Tactical Destroyer) had no mode either: no Sharpshooter rocket/light missile damage, velocity, targeting or sensor bonus, no Defense resists/signature/shield recharge, no Propulsion.
  • Hecate Propulsion gave an afterburner the speed and cap bonus. pyfa's handler boosts only High Speed Maneuvering modules (microwarpdrives).
  • Hecate Defense (armor repairer cycle ×1/1.5) and Confessor / Svipul Defense (remote repairer cap need ×1/1.5) were missing.
  • Sharpshooter damage used a rounded 33.3% instead of ×1/0.75: Confessor volley 1181 → 1182, Hecate 63 → 64 DPS.

What changed

  • New PYFA CORE section modes:
    • MODE_EFFECT_ROWS, generated by the new tools/gen_mode_table.py: every effect of every mode item (6 hulls, 18 modes, 83 rows) run through pyfa's handlers. Each row has its target (ship, module or charge), attribute, multiplier, stacking group and the handler's exact module/charge filter. The generator asserts that every penalized mode row is alone in its stacking group (no other carrier shares it, and no two rows of one mode hit the same item), so it multiplies in unpenalized, as in pyfa.
    • resolveModeKey (the default mode) and modeRowsMult (applies the filter).
  • Engine: the five hand tables are gone. The mode rows feed every stat that reads those attributes:
    • weapon damage and rate of fire (turrets, missiles, ammo list)
    • weapon range (optimal, missile velocity, flight time)
    • targeting range, sensor strength, signature radius
    • cruise speed, propulsion speed factor and MWD signature bloom, agility
    • shield recharge, repair cycle and module capacitor need
    • module reactivation delay (Anhinga Tertiary MJD ×0.1, so cycle-time was re-verified)
    Resists still come through RESIST_EFFECTS.
  • UI:
    • The mode selector is now on every hull with modes: Skua (Sharpshooter / Defense / Propulsion), Anhinga (Primary / Secondary / Tertiary, Primary by default as in pyfa).
    • The "How this is handled" note has an Anhinga version.
    • Weaknesses card: "weakest damage type (NN%)" now reads "least resisted overall (NN% resist)", where NN = 100 − the old figure (Erik's option 2).
  • Tooling:
    • tools/independent_checks/compare_modes.py (new): every golden fit on a mode hull, in every mode, against the oracle. It compares DPS, weapon range, targeting, sensor strength, EHP, signature, cruise and boosted speed, align time, passive shield regen, armor repair and capacitor drains. Both it and gen_mode_table.py are now in the update-check chain (13 steps).
    • audit_firepower.py and pyfa_update_check.py no longer read the removed table.
  • Oracle fixes (pyfa_fit_oracle.py, golden_oracle.py). The new comparison found three gaps in the reference itself (LESSON #27):
    • no Item.getAttribute, so every crystal's cap-need bonus was silently skipped
    • no ship mass (pyfa copies mass, capacity, volume and radius into the attributes)
    • a slot that listed its charge before its module lost the pairing
    Also added: Character.getSkill, itemModifiedAttributes[] / force, and fit.extraAttributes. The oracle now records any AttributeError from its own stand-ins in fit.oracleGaps. Over all 190 fits there are none. compare_resists.py is still 0 of 190.

Not changed (in DEVIATIONS.md)

  • Tactical Destroyers still default to Sharpshooter (pyfa: Defense, the first mode item). That is an input choice. The Anhinga defaults to Primary, as in pyfa.
  • Mode effects on stats the tool doesn't show: turret tracking (Svipul), remote repair and remote shield boost amounts, weapon-disruption and sensor-dampener resistance.
  • Found along the way: missile range. pyfa's missileMaxRangeData adds the ship radius to the flight time, splits it into whole seconds, counts acceleration at half speed and subtracts the ship radius. The tool uses velocity × flight time. This is a new deviation entry and a backlog item, not part of this change.

Lesson for future models

  • A reference that swallows errors the way pyfa does can hide its own gaps. Log errors from missing stand-ins, and when the tool and the reference disagree, debug both (LESSON #27).
  • When pinning pyfa's rounded display (e.g. "1.91k"), cover the whole bin including its rounding edge: 1905–1914.99 rounds to 1905–1915 in the tool.
  • Compare on more stats than the one you're changing. The capacitor-drain comparison caught the crystal gap, which had nothing to do with modes.
  • A mode is just another carrier (LESSON #26). Generating its rows with the handler's real filter showed that a hand table had spread one hull's MWD-only bonus to afterburners.
