Kills picked on the Fleet tab; the victim; Retry for zKillboard; Near You's reach

FleetIntelzKillboard 2026-10-31 · v2026.10.31.2

Why

The owner asked for four things in this delivery:

  • Pick the kill on the Fleet tab. "next iteration of this should also move the 'which kill to analyze' decision to the fleet tab". Opening a row on Intel was "not very intuitive or easy to read with a constantly changing list on both sides of the page". He added "kills in the feed should be links as well. same mechanic".
  • Analyze the victim. "similar top level analysis of the victim is good to have".
  • A retry for zKillboard. From a screenshot of the Fleet tab with every pilot saying zKillboard wasn't answering: "the user is going to try refreshing the page as a result of the 'Try again in a few' note. we need a refresh / retry icon that will retry the attempt. even if we need to add a timer per refresh to limit the number of attempts per minute or something."
  • A shorter Near You. "limit the range of what shows up in Near You to (alert range +5)".

The mockup settled three choices:

  • Solo kills go to the Fleet tab too.
  • The victim card sits above the fleet.
  • The separate Fleet ▸ / Pilot ▸ button was dropped. He asked "is there any reason to have the fleet or pilot button at this point? i'd like your opinion"; with the label doing the same thing there wasn't.

What changed

  • Every kill opens on the Fleet tab:
    • from its label in the Feed (HOSTILE KILLED and the rest are now buttons);
    • from a Near You badge;
    • from each kill in a Near You row that's been opened.
    A badge for several kills shows the newest, and lists them all in the header to pick from, as they were when it was clicked. New kills arriving on Intel don't change that list (LESSON #110). The Fleet ▸ / Pilot ▸ button is gone, and so is its hover text, which still spoke of the card removed in v2026.10.31.1.
  • The victim is a new card above the fleet, built from the killmail's own fit: raw DPS and damage mix, weakest to, weapon reach, tackle and EWAR with reach, and EHP. There is no time to kill (LESSON #108).
  • zKillboard not answering:
    • The pilots card has one ↻ Retry. It counts down while the page's pause after a failure is on (1 minute, doubling up to 10) and while the request budget is spent, so pressing it can never ask sooner than the page already allows (zkbRetryHtml). The System Analyzer's three Retry buttons now work the same way.
    • The pause is kept in localStorage, so a reload or another tab waits it out too.
    • The message now says reloading won't bring zKillboard back sooner.
    • Each failed row says it in short ("zKillboard didn't answer (ZKB-01): Retry is above"), with the full text on hover.
    • The summary says none could be looked up, instead of "Adds up as the pilots come in…".
  • Near You lists systems up to 5 jumps past the alert range. Systems farther away, or with no gate route, stay in the Feed. Its line says "within N jumps". If your own system isn't known, it lists all of them as before.

Lesson for future models

LESSON #110: don't make people pick from a list that is still moving. Take a snapshot when they ask, show it where nothing else moves, open the likeliest choice at once, and use one control per action.

Added under LESSON #106: a pause kept only in memory ends at a reload, the very thing an error message tends to invite. Keep it where every load sees it, and give the wait a Retry that counts it down.
