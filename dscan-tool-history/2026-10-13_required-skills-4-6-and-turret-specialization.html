Required skills 4–6 and the turret Specialization gate

Bug fix 2026-10-13 · v2026.10.13.20 → v2026.10.13.21 · Erik: "ok make the fix and then move on to phase 2"

What was wrong

pyfa decides whether a skill bonus applies to an item with requiresSkill(). That reads the item's direct required skills from the SDE table requiredskillsfortypes. For every published type, that table matches attributes requiredSkill1–6 exactly (checked: 0 mismatches). The tool read only requiredSkill1–3. Three things were wrong as a result:

ProblemWhoEffect
Gunnery is in slot 4, so Gunnery-gated bonuses were skipped: Sharpshooter, Trajectory Analysis, Controlled Bursts, Tracking Enhancers/ComputersQuad Mega Pulse Laser II, Triple Neutron Blaster Cannon II, Quad 800mm Repeating Cannon IIRevelation, 2× QMPL II + TE II: optimal 18,150 → 24,956 m, falloff 16,000 → 24,000 m, weapon drain 41.7 → 31.2 GJ/s
Turret Specialization (+10% damage) was gated on "has a requiredSkill3", used as a stand-in for "is T2"19 T1/meta/faction capital short-range turrets, whose slot 3 is Gunnery or Motion PredictionRevelation, 2× QMPL I: DPS 101 → 92 (the stand-in gave +10% that doesn't exist)
Only one racial Drone Specialization was countedAralez (requires Gallente and Caldari Drone Specialization)2× Aralez: drone DPS 99 → 109 (pyfa Effect1730 applies each skill to drones requiring it)

Fix

  • REQUIRED_SKILL_ATTRS = [182, 183, 184, 1285, 1289, 1290].
  • New requiredSkillMatchCount() helper. A bonus now applies once per matching required skill, as in pyfa.
  • New TURRET_SPECIALIZATION_SKILL_IDS: all 31 turret Specialization skills, each +2%/level in the SDE. It replaces the requiredSkill3 stand-in on both turret DPS paths.
  • The fighter Specialization check still uses requiredSkill3. It was checked against the SDE and matches the real rule for every published fighter.
  • Other items with skills in slots 4–6 are covered by the same change: the four T3 cruisers, four dreadnoughts and seven covert/recon/black-ops-type hulls, plus EWAR, mining and salvage drones. None changed any existing fit.

Verification

  • Expected values come first, from tools/independent_checks/check_required_skills.py.
  • Three new constructed golden fits. v.20 fails 5 checks on them; v.21 passes 139/139, and the parse tests pass 280/280.
  • A full output diff of every golden fit, v.20 → v.21, changed only the three new fits.
  • The weapon-range and module-state generators and the table audit all still run clean.

Lesson for future models

  • #18: "does the item require skill X" must check all six slots. Never use an attribute's presence as a stand-in for a category (T2, size, race); check any such gate against the SDE for every published item it could touch.
  • #19: found while doing this. Some pyfa skill handlers filter on the skill itself (requiresSkill(skill)), and the recorder returned no hits for them without any error. run() now takes carrier=, records skill? when it's missing, and the audit prints a warning. None of the existing tables were affected.
