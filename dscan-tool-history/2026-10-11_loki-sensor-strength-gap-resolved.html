Loki sensor-strength "open gap" — resolved: different subsystem, not a bug

Context: per the owner's request ("take a look at the loki sensor strength issue first"), re-investigated the long-standing flagged open gap on the Navigation & Targeting card's Sensor Strength stat: a real pyfa figure pasted for the loki_zkb138935092 golden fit (138935092) showed 20.4 (Ladar) vs. this tool's 17, despite an earlier "exhaustive" live-ESI sweep of the hull, all 4 fitted subsystems, every module/rig/charge/booster, and every skill in the Targeting/Engineering/Electronic Systems groups finding nothing that touched attributes 208-211. That sweep was real but incomplete in one specific way, found this time.

What was actually missed

The earlier sweep checked only the 4 subsystems actually fitted on this killmail (Immobility Drivers/Covert Reconfiguration/Launcher Efficiency Configuration/Intercalated Nanofibers). It never enumerated the other, unfitted variants available in each of the Loki's 4 subsystem slots. Confirmed live via ESI market groups (Minmatar Core/Defensive/Offensive/Propulsion Subsystems, 3 real variants per slot, 12 types total) that exactly one of the 12 — Loki Core - Dissolution Sequencer (type 45631) — carries an effect (id 3893) applying attribute 1446 (subsystemBonusMinmatarCore, base value 15) as a PostPercent bonus to attribute 209 (Ladar) specifically. Its own description text confirms the mechanic: "improved sensor range and target acquisition speed... protection against hostile ECM."

That container attribute (1446) is itself scaled up by the required skill, Minmatar Core Systems (30547, effect 3843) — the exact same "required-skill-scales-a-container-attribute" architecture that caused the earlier Tengu/Proteus EWAR subsystem bug (documented in dscan-tool-architecture.md), now confirmed on a different attribute/subsystem family entirely.

The math checks out exactly

17 (hull base Ladar, already confirmed correct via everef.net's own type data in the earlier investigation) × 1.15 (Dissolution Sequencer's base +15%, skill level 0) = 19.55. This codebase's own established pattern for these per-level subsystem container bonuses is +1 percentage point per skill level (5 levels, same convention seen elsewhere in SUBSYSTEM_ROLE_BONUS). At Minmatar Core Systems V: 1446 = 20, so 17 × 1.20 = 20.4 — an exact match to the pasted pyfa figure.

The killmail/golden fit actually fits Loki Core - Immobility Drivers (type 45633), not Dissolution Sequencer. Immobility Drivers carries zero dogma attributes or effects touching 208-211 — reconfirmed exhaustively this pass. So 17 is the fully correct answer for the fit the tool is actually modeling; the pasted 20.4 almost certainly came from a pyfa session showing a Loki fitted with the other Core subsystem variant, not this fit.

Caveat (same bar as everything else in this file)

The exact skill-level-to-percentage mapping (1446 = 20 at level V) is inferred from this codebase's established convention for subsystem-container bonuses, not independently re-verified against a live character — ESI's type endpoint only exposes the level-0 base value, the same limitation the original investigation ran into. The mechanism (which subsystem, which attribute, which skill) is fully confirmed live; only the precise magnitude at max skill rests on pattern-matching rather than a direct character read. Flagged here rather than silently treated as 100% certain.
