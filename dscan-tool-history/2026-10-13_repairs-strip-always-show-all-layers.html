Repairs strip always shows all three layers

2026-10-13 · index.html

What changed

The owner, looking at a buffer-armor fit (144,624 armor EHP of 183,933 total, dominant layer): "looking at this buffer armor fit and the repairs section shows the row for shields instead of armor. is that because only the passive regen has a value to be noted?" -- correct diagnosis. The Repairs strip previously only rendered a row for a layer when tankStyle[layer] was non-null, and Armor/Hull only get populated there when an active repairer module is actually fitted (no passive regen mechanic exists for either, unlike Shield, which regens passively on every hull whether or not a Shield Booster is fitted -- see the 2026-10-12 passive-shield-recharge fix). So a pure buffer-armor fit (plates/extenders, no armor repairer) showed only a Shield row, with the dominant Armor layer -- and Hull -- simply absent from the section entirely, even though Resistance directly above it always shows all 3 layers.

Floated an alternative (keep Armor/Hull as their own rows, same per-layer Break Point column, just render dashes when there's nothing to show) rather than merging everything into one combined row -- the owner confirmed merging wouldn't work anyway since Break Point is inherently per-layer, not a single fit-wide number. Then: "i think it's beneficial to show all three layers because the dashes in and of themselves both indicate that something isn't missing in the data, and that there is, in fact, no repair value. further highlighting if something is a buffer fit for example."

Implementation

The Repairs strip now iterates the same layers list Resistance uses (any layer with raw HP > 0) instead of filtering to layers.filter(l => l.rep) first. A layer with no rep module (l.rep null) still gets its own row: all 4 value cells render as — (reusing the existing .repairs-cell.empty styling), and the Break Point cell does too -- bpDps stays explicitly null rather than being coerced to 0, because 0 dps would misleadingly read as "unbreakable"; the honest statement is "no sustained regen exists on this layer to race against at all, it's pure buffer." New .repairs-bp.empty CSS rule mutes that dash to --text-faint instead of leaving it in Break Point's red. The dash still carries hover text ("No repair module fitted on this layer — pure buffer, no sustained regen to race against") via the same title=""-on-a-wrapping-element pattern the rest of the card uses (the .repairs-bp span is a real HTML <span>, not an <svg>, so the plain title="" attribute is correct here -- no SVG <title> child needed, unlike the icon fix earlier today). The strip's own footer note gained a trailing sentence explaining the dash convention.
