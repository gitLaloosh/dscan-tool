"Show other attackers" toggle bug fix

Date: 2026-10-10   Status: Fixed, reproduced before and after in real Chromium, 28/28 regression PASS, byte-identical diff

Reported by the owner: "after clicking on the 'show other attackers' button for a pilot's last kill, then hiding the list again, any subsequent attempt to show the list fails. it just changes the button text but does not show the list."

Root cause

In renderLastKill()'s toggle handler, the "hide" branch did two things: remove the attacker-list CSS class, and clear listEl.innerHTML. But it never reset the loaded flag back to false. The "show" branch only re-renders the list when !loaded — so after the first hide, the handler believed the content was still cached (loaded stayed true) even though the actual DOM content had just been deleted. Every "show" after the first "hide" skipped re-rendering entirely, leaving an empty container while still flipping the button text to "Hide other attackers" — exactly the reported symptom.

Reproduction

Reproduced live in real Chromium (Playwright) against the pre-fix canonical file, with zKillboard/ESI mocked for a pilot with 2 other attackers on their last kill: show (1st click) correctly rendered 2 attacker rows; hide (2nd click) correctly cleared them; show again (3rd click) left the list empty while the button said "Hide other attackers" — byte-for-byte the reported bug.

The fix

Hide the list via style.display = 'none' instead of discarding its rendered content. loaded now stays accurate — true exactly when the DOM still actually has the content — so re-opening after a hide just toggles display back, instantly, with no re-fetch. The "show" branch's if(!loaded) guard and everything else is unchanged.
