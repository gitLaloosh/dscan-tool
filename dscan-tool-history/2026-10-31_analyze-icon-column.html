The analyze icon in its own column

IntelUI 2026-10-31 · v2026.10.31.7

Why

The owner sent a screenshot of v2026.10.31.6's Near You: "I dont think the placement of the "send to system analyzer" button was intended to look like that." The icon sat far to the right of short system names, in empty space.

The cause: layout D put the icon after the system column, and the page makes that column as wide as the longest system name in EVE (Tash-Murkon Prime, the owner's rule from 10-30, so the columns never shift). The mockup had sized the column to the names on screen, so there the icon sat beside the name. No check caught it, because the page checks load only short made-up system names.

Two mockups followed. First the icon moved to just before the name (option E), which the owner liked, and he asked whether the Feed should get the icon too; with it only in Near You, the two lists' names would no longer line up. Then he had a different idea: "utilize this space to place the button. that way if it doesn't show up, it's not leaving the rest of the content looking misaligned. just looks like a column that either has the button or does not. just have to account for double digit jumps." That mockup (option F, both lists side by side) is what was built. For phones he picked the icon under the jump count, next to the expand arrow, so what was reported keeps its width.

What changed

  • Both lists, line 1: the jump count, a column with the analyze icon or nothing, then the system, the tags and the time. The kill badges, what was reported and the kill lines start under the system name, so a row without the icon has an empty cell and nothing else moves.
  • The jump column is as wide as "88 Jumps" or the In System label, whichever is wider, measured in the font the browser draws (--it-jw, set by itSysWidths, one width for both lists so their names line up across the card).
  • The Feed gets the icon on report rows. It analyzes the whole system, as Near You's does: everything reported there in the time set, not only that line, and its hover says so. Kill rows and clear rows have none. It reaches systems Near You doesn't list.
  • On a phone the icon sits under the jump count, to the right of the expand arrow (32 px each).
  • itAnalyzeHtml draws the icon for both lists; itCanAnalyze answers once per system per draw.

Checks

  • intel_layout_check.py: the icon one column gap from its system on every row and, for the busy row, at every split width (905–1700 px) with the table's system column and with a 160 px one; the kill badges and names under the system; the jump column fits "88 Jumps" and In System and no count runs into the icon; the system names and icons the same distance from each list's left edge in Near You and the Feed; on a phone, the icon under the jumps beside the toggle in both lists.
  • intel_rows_check.py: the Feed's icon on reports, its hover; none on kill and clear rows; pressing it sends both of a system's reported pilots, not only that line's.
  • Mutants (each made the checks fail): the icon after the system again; a 62 px jump column; the kill badges under the icon; on a phone the icon back on line 1; no Feed icon; the Feed icon on kill rows too; the Feed without its icon column (7 of 7 caught).
  • run_checks.py --tier area --area intel,layout: 8 lints and 17 page checks. intel_assess_check expected the phone toggle at 36 px; it is now 32 px so it fits beside the icon (an intended change, expectation updated). intel_guard_check was flaky under load and passed alone.

Lesson for future models

LESSON #114: size a mockup the way the page sizes it, and test with names as long as the real ones. A mockup that sized the column from its sample rows looked right; the page sized it for the longest name in EVE, and the icon floated in empty space. Short made-up names in the checks hid the same gap. Use the page's own sizing rules in mockups, and sweep layout checks with columns as wide as the real data makes them.
