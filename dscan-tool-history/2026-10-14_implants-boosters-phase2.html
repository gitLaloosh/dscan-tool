Implants and boosters, Phase 2: weapons and drones

FeatureBug fixTooling 2026-10-14 · v2026.10.14.12 → v2026.10.14.13 · Erik: "ok, proceed with implants phase 2"

What changed

  • Weapon damage and rate of fire, charge damage, drone damage: the implant and booster rows from IMPLANT_EFFECTS (already generated in Phase 1) now join the hull damage rows that hullWeaponMods / hullDroneMods apply to every weapon, charge and drone they match. In pyfa they are unpenalized multipliers on the same attributes, so this is exact. Confirmed weapons, the cargo-ammo estimates and the weapons' capacitor use all read them.
  • Ranges: turret optimal and falloff, missile velocity and flight time rows join the weapon range sources (Frentix, Sooth Sayer, Strokar, Deadeye hardwirings, Halcyon B...). Missile range goes through pyfa's own missileMaxRangeData as before.
  • Precursor spool-up: the Mimesis set's bonus to damageMultiplierBonusMax is applied to the maximum spool.
  • Smartbombs: an implant on the smartbomb cycle (Energy Pulse Weapons EP-70x) now changes its DPS too; its capacitor use already did in Phase 1.
  • Drone control range: boosters that add to it (Halcyon Y, Free-Zone) are added before the hull multiplier, as pyfa's increase on fit.extraAttributes; the hover names them.
  • The Fit card note now reads "Included in every number above, as in pyfa." Implants also touch stats the tool doesn't show (turret and drone tracking, warp speed, CPU / powergrid, mining, fighter ranges).

Found on the way

  • Precursor and Vorton falloff: these weapons have no falloff attribute; the tool read 0, pyfa reads the SDE default 1 (1 m, 1.25 after Trajectory Analysis). Fixed (LESSON #22). Six goldens re-pinned 0 → 1 and five more fits show 1 m; nothing else moves.
  • Oracle: drones in space added (drones=, run as pyfa's Drone.calculateModifiedAttributes), and fit.extraAttributes is now the ship's attribute dict with pyfa's Ship.EXTRA_ATTRIBUTES (drone control range starts at 20 km; before, a separate empty dict).
  • My own check was wrong first: the new DPS comparison multiplied by 1 + damageMultiplierBonusMax, whose SDE default is 0.5 on every item, so every turret came out 50% high (Rifter 288 vs Erik's pyfa 192). pyfa's calculateSpoolup needs the per-cycle value too. Fixed in the check before it was used for any pin.

Lesson for future models

  • LESSONS_LEARNED #22 (extended): a missing attribute is its SDE default in both directions: the tool read falloff 0 where pyfa reads 1, and a check read damageMultiplierBonusMax 0.5 where pyfa's consuming code guards it. Read the default, then the code that consumes the value.
  • Reuse the shape that already exists: implant rows fit the hull damage rows exactly, so one loop wired every weapon, charge, drone and the capacitor use of weapons at once.
