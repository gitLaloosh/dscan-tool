Intel: a pilot whose surname is a system's name

Page 2026-11-06 · v2026.11.06.3

Why

  • Build queue 018, Project doc roadmap/intel-surname-system-plan.md. The owner's Feed screenshots (2026-11-06): one scout reported eight times, every row headed by a system 6 jumps away that was really the second word of the scout's name, with the first word left over as "not placed". Lines naming only the scout and his ship were placed in that system too, which can raise false alerts. The owner's answer for those: "No report now; tie-in later (Recommended)". The real names stay out of the repository; the checks use made-up ones.

What changed

  • Longer names looked up: each whole system together with the plain, unplaced words right before and/or after it (2–3 words, at most 37 characters) goes into the same /universe/ids/ batch as today's names. No new request.
  • Two or more systems: a system inside a pilot's name ("Ressa Jita T5ZI-S") is that pilot while another system is left, and this is now decided before the Feed's distance ring (the ring used to keep the wrong, nearer one). The whole name becomes the pilot chip, a ship in brackets after it pairs with it, and there's no "or Jita?" note or word left over.
  • Only one system, inside a pilot's name ("Ressa E-VKJV Sabre"): the line names the pilot and no system, so it makes no row, no Near You change and no alert. It still counts as the channel's last line. Only when the name is typed in its own capitals (or dragged in) and the words beside the system aren't a pilot on their own; otherwise the system stays the system, as before.
  • Nothing looks different; only which system and pilot a line shows, and some lines no longer make a row.

Checks

  • intel_place_check.py: the plan's made-up cases (two systems, either order, a three-word name, a ship in brackets, dragged in, the ring order, one system inside the name, and the cases that keep the system); no name looked up holds two systems; one name batch; Intel shows no error of its own. Mutants: the longer names not looked up, the pilot check after the ring, a one-system line still making a row, the capitals rule dropped, the "neighbour alone is a pilot" rule dropped, a neighbour that is a system taken in, each caught. Forcing only the system's own word changes nothing (the neighbours are already free for the pilot lookup), so that one has no case.

Lesson for future models

  • LESSON #139: a new loop read one word before a line's start and threw for every line that began with a system; Intel caught it and showed "Intel stopped reading (APP-01)" on the card, so every report vanished while the check printed "no page errors". Checks of a part that catches its own errors now also assert its error line is empty.
