Tactical Destroyer Mode selector — modular card + info link in-row

2026-10-12 · dscan-tool.html · feature backlog item (UI polish, no calc-accuracy impact)

The request

Three asks on the existing Mode selector: (1) move the "How Tactical Destroyer Mode is handled" text link into the same row as the mode icons, (2) keep click-to-expand behavior for the explanation, (3) wrap the whole thing in one self-contained container the way the other cards (Firepower, Resistance, etc.) already are, so it's as easy to move/reuse as a unit.

What changed

Previously this was bare page-level markup: a .td-mode-row div (label + icons) followed by a separate sibling <details> disclosure below it — two independent pieces, not one container.

Now it's a single <div class="fit-summary td-mode-card"> — the same card shell every other card in the tool uses — wrapping one <details> element. The mode-icon row is that details element's own <summary>: label, icons, and the "How this is handled" link (pushed to the row's right edge) all live in one row, and clicking anywhere on that row except a mode icon toggles the explanation open/closed underneath.

To keep mode-icon clicks from also toggling the explanation (since the icons now sit inside the <summary>, and a click on any of its descendants normally bubbles up and triggers the browser's native toggle), each mode button's click handler now calls preventDefault()/stopPropagation() before doing its existing job (switching the active mode and re-rendering). Both places that wire these buttons (the Pilot Analyzer's per-fit-tab renderer and the Fit Analyzer tab) got the same small addition.

Verification

Playwright-driven functional test against the live post-change code (not just visual inspection):

  • Clicking a mode icon switches mode and does not open the explanation — confirmed false → false.
  • Clicking the "How this is handled" link opens it — confirmed false → true.
  • Clicking it again closes it — confirmed true → false.
