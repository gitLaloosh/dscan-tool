Bug #1: an EFT fit pasted into the D-Scan box

Report: pasting an EFT fit into the D-Scan Analyzer and submitting it listed several modules as contacts, instead of saying the paste wasn't a scan.

Reproduced on the real page (Playwright, ESI served from the SDE) with a Rifter EFT: "Done — 7 type(s) recognized", with Damage Control II, 400mm Steel Plates II, the MWD, scram, web and rigs each shown as a "not a ship" contact card.

Cause: the D-Scan tab sends every line's text to ESI's name resolver. Every module name is a real item, so every one resolved. Nothing checked what kind of item it was.

Fix (presentation and input handling only, no calculation):

  • detectFitPaste(): if the first non-empty line is an EFT header ([Ship, Fit name], the same regex parseEftFit() uses, now the shared constant EFT_HEADER_RE) and has no tab, the tab stops before any lookup. It shows "That's a ship fit (EFT format, Rifter), not D-Scan results" and a button, Analyze it in the Fit Analyzer, that moves the paste to the Fit Analyzer and runs it. A real D-Scan row is tab-separated, so it can't match.
  • NOT_IN_SPACE_CATEGORY_IDS: lines that resolve to a category that can never be an object in space are set aside as "Fitting items" instead of contacts, with a hint pointing to the Fit Analyzer. Categories from the SDE (categories.0.json): Module 7, Blueprint 9, Skill 16, Implant 20, Apparel 30, Subsystem 32, Structure Module 66, SKINs 91, Expert Systems 2100. Charges (8) are deliberately not listed, because scanner probes and bombs are charges and do appear on D-Scan. This covers a module list pasted without its header.
  • The status line now counts contact types, and fitting-item lines separately.

Bug #2: the PANIC has no Active state

Report: on the Fit card, a Pulse Activated Nexus Invulnerability Core offered only offline and online; it should also offer active.

Finding: the tool matched pyfa exactly. pyfa has no Effect6719 handler class (eos/effects.py), so its Item.isType('active') is false and Module.isValidState refuses ACTIVE. CCP's data disagrees: effect 6719 moduleBonusIndustrialInvulnerability is an activation effect (effectCategory 1) with a duration attribute (2788 panicDuration, 240 s), and the item description says it makes the Rorqual and its fleet's subcapital mining and hauling ships nearly invulnerable for a short time. Erik is right about the game.

tools/independent_checks/check_panic.py (new, in the update-check chain) scanned every published module for this pattern: the PANIC is the only one. It also ran pyfa's handlers on a Rorqual with no PANIC, PANIC online and PANIC active: identical attributes in all three, because pyfa computes nothing for it.

Fix:

  • ACTIVATABLE_WITHOUT_PYFA_HANDLER_EFFECTS = {6719} lets moduleCanBeActive() accept it. This is an input deviation (listed in DEVIATIONS.md); setting it active changes no number.
  • It defaults online (added to MODULE_DEFAULT_ONLINE_EFFECTS): a one-use, 4-minute emergency button, the same reasoning as Erik's D3 for MJDs and cloaks. The golden oracle's default list matches.
  • New MISC_TRAIT_EFFECT_INFO, keyed by effect id (the PANIC's group, "Super Weapon", is shared with doomsdays, so the group-name table couldn't be used). The EWAR / Misc card now flags a fitted PANIC: what it does within its range (attr 54, 200 km) for its duration (attr 2788, 4 min), both read from the item; that the ships can't deal damage, warp, dock, cloak or jump while it runs; one use, then it burns out; and that the stats don't include it. Set active, the flag reads "RUNNING". This also closes the architecture backlog item "PANIC Misc flag".

Real page: the PANIC button cycles online → active → offline → online; the flag switches to RUNNING when active and disappears when offline.

Lesson for future models

  • LESSONS_LEARNED #29, pyfa's gaps are not the game's rules. "Matches pyfa" was true and still wrong. When a player says something exists in game and pyfa disagrees, check CCP's data. If pyfa simply doesn't model it, change the input, never invent numbers, describe the mechanic in words, list the deviation, and keep a scan in the update check.
  • LESSONS_LEARNED #30, a name that resolves is an item, not necessarily the right kind of item. Check the input's shape first, check the resolved category belongs there, and test a new input check against every real paste from every starting row.
