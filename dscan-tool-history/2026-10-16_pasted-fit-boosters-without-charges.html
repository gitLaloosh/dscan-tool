Pasted fits: Cap Booster / ASB with no charges

FeatureInput rule 2026-10-16 · v2026.10.14.23 → v2026.10.14.24 · Backlog "Fit Analyzer: cap-booster/ASB with no charges found". Erik (earlier): "we should probably call out the fact that it's missing charges and flag it as a weakness if no charges are found"; then "let's go with option A".

The rule

  • A pasted fit (Fit Analyzer) has no "used them all up" alibi like a killmail. So a Capacitor Booster or Ancillary Shield Booster with no charge loaded and none in cargo or the fleet hangar is empty:
    • the Capacitor Booster injects nothing;
    • the ASB repairs from capacitor, so its cap need counts in the best case.
  • The Weaknesses card shows a red "!" row: "No charges for its <module>", with "none loaded and none in cargo, so it can't inject capacitor" or "...so it repairs from capacitor instead".
  • On the Capacitor card, the booster's icon is greyed with a red dashed ring. The caption reads "<module> has no charges in the fit, not injecting" (or "running on capacitor (N GJ/s)"). An empty ASB has no out-of-charges toggle.
  • Killmails (Pilot Analyzer) are unchanged: their charges may have run out in the fight, so the largest compatible charge is still assumed (v.27 best case). A charge found in cargo counts in both analyzers.

How

  • estimateHpAndDps(..., options) takes a new 9th argument, {fitSource: 'eft'}. The Fit Analyzer passes it, keeps it on f.input, and recomputeFitWithStates passes it again, so module-state changes keep the rule.
  • Engine:
    • capBoosterChargesMissing clears the "assume the best charge" fallback.
    • asbChargesMissing keeps the ASB's drain in capSimInputs.best and activeDrainPerSec.
    • Each boost has source: 'none', and capacitor.chargesMissing lists them.
  • Test harnesses (run_regression, dump_results, compare_cap_sim) pass a golden fit's fitSource. compare_fit_stats.py keeps an empty ASB's drain in the pyfa comparison, since pyfa without charges runs it on capacitor too.
  • DEVIATIONS.md (inputs) updated. pyfa itself only uses the charge in the fit, which is what the pasted-fit rule now does.

Lesson for future models

  • When an assumption depends on where the input came from (killmail vs pasted fit), pass the source explicitly and carry it through every recalculation path, not just the first render. The page check repeats the check after a module-state change for that reason.
