Content-Security-Policy and the Phase 0 hardening

Page 2026-11-07 · v2026.11.07.3

Why

  • Build queue 023, Project doc roadmap/sso-hardening-plan.md: the EVE SSO plan's Phase 0 step 6b. The owner, 2026-11-07: "is 6b planned and in the queue? if not, let's do that right now." No login code is included.
  • The SSO security review (Project doc roadmap/sso-security-review.md, made-up data, local only) found that a crafted fit name could run script in the page; 021 (v2026.11.07.2) fixed that hole. Once a login exists, any script that gets into the page could read the tab's login, so this makes the next hole much harder to use (a policy that refuses injected script) and much harder to create (a lint on how markup is built), and keeps tokens from ever going anywhere but CCP.

What changed

  • A Content-Security-Policy as a meta tag before the script: only the page's one inline script runs, named by its sha256; requests only to ESI, login.eveonline.com (for Phase 1), R2Z2 and zKillboard; images only from EVE's image server, data: and blob:; workers from blob:; no plugins, forms or <base>. Injected handlers and scripts are refused by the browser. A meta tag can't set frame-ancestors or reporting; GitHub Pages can't send headers.
  • No referrer: <meta name="referrer" content="no-referrer">. Nothing the page calls needs one.
  • The 27 inline onerror handlers on images (which the policy would refuse) became data-imgfail kinds read by one capturing listener: hide (14), remove (9), none, next, next-block and initials. The profile portrait's initials are now worked out in profileInitials and put in as text; before, the pilot's name was built into a script string inside the attribute.
  • Nothing users see changes. Nothing kept in the browser changes.

Tools and checks

  • tools/csp_hash.py: --write puts the script's hash in the policy after an edit; --check (in run_checks.py, the pyfa chain and the pre-commit hook, on the staged copy) fails on a stale hash, a second script, the meta after the script, no referrer meta, 'unsafe-inline'/'unsafe-eval', or a policy other than the one written in the tool. It hashes as the browser does: HTML turns CRLF into LF first, so a Windows checkout (.gitattributes text=auto) gets the hash of the page GitHub Pages serves, rather than writing one that would stop the live page.
  • Page checks open the page with bypass_csp=True (95 calls in 63 files): they test behaviour and need eval, modified copies and mutants, which the policy rightly refuses. tools/page_checks/csp_check.py is the one check with the policy on: the page served over HTTP from its folder, a tour of every tab, the Fit and Pilot Analyzers, Local, the profile and My Fits, and Intel with its worker, with 0 violations; an injected <img onerror> refused; each data-imgfail kind as its old handler (the initials as text); no Referer on 214 requests; a CRLF copy runs.
  • tools/check_html_sinks.py: a ${...} in a template that builds HTML must be escapeHtml(...), a number, a constant or a builder (a ...Html( function, or its short list). Its own tokenizer reads strings, comments, nested templates and regex literals: 794 HTML templates, 2,480 ${...}. The 1,691 that pass none of the rules today are in tools/html_sinks_baseline.json, which only shrinks (adding to it needs the owner's OK in a pull request). It also fails on inline on...= handlers, single-quoted attributes built from ${...}, and innerHTML = a bare variable not in the baseline. Builders ending in Html (133 of them) pass by the page's naming convention rather than one by one. To close the gap that leaves (the owner, asked: "yes"), two more rules: a builder may not return one of its own arguments unchanged in any branch, and markup glued with + must add only escaped text, numbers, constants, builders or literals. Today's page has one such + (a piece of a builder's own output, in the baseline: 1,692 entries) and no builder returning its argument.
  • check_request_gates.py: an Authorization header only in esiFetch; login.eveonline.com only from functions in SSO_SITES (empty until Phase 1). Comments don't count. The Phase 1 rules (a 401 not retried, token answers parsed only as JSON) are written as TODOs in its docstring until the code exists.
  • check_pii.py: the tool's public contact address (the SSO plan's D4) and the two public Client IDs allowed by name; JWT-shaped strings with any payload, and long opaque values set on a token / code_verifier / refresh key, flagged; made-up test tokens start madeUp.
  • Mutants, each caught: a stale hash (nothing runs), no policy (the injected handler runs), zKillboard dropped from connect-src (a violation in the Pilot Analyzer), 'unsafe-inline' in script-src, no referrer meta (a Referer on every request), the initials only removing the image (csp_check and profile_check), the initials as HTML, the hash tool without the CRLF step (its self-test); in the lint, an unescaped title, an onclick= in a template, a single-quoted attribute, a builder returning its argument and markup glued around an unescaped name; in the gates, a login request in an unlisted function and an Authorization header outside esiFetch (plain fetch, and headers.set); in the personal-data check, a fake JWT, a second address, a token value.

  • Page size: 763,839 → 762,547 bytes gzipped (gzip -9): the handlers' text was longer than the listener and the meta tags.

Not in this delivery

  • X-User-Agent on ESI calls (Phase 1: a custom header makes every ESI request preflighted; measure that first) and any login code.
  • 022 (the logo) comes after this, at the owner's choice: its tab icon is served from the site itself, so it will add 'self' to the image sources (noted in its queue file).

Lesson for future models

  • LESSON #145: a security policy the checks switch off is untested. One check runs the page with it on; every other opens with bypass_csp=True. Never turn it off in that one check to make it pass, and hash the script the way the browser does.
