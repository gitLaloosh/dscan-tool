New check: tools/check_card_names.py

It is the 35th step of the update-check chain. It reads every string the page can show: JavaScript string and template text with comments skipped, the HTML text and attributes, and every ERROR_CODES field. It fails when:

  • a listed name is typed by hand (also with other capitals, so "Navigation & targeting" is caught);
  • text says "<Name> card" for a name that isn't listed;
  • an old name (its RETIRED list: "their damage on you", "last-kill box", "threat view"…) is still shown;
  • a helper or {card:key} uses a key that doesn't exist, or a helper is still handed a title;
  • ${cardName( sits inside a quoted string (it would print literally or break the script);
  • CARD_NAMES and roadmap/card-names.md disagree.

The page checks now read titles from CARD_NAMES instead of literal text. layout_check.py also checks that every card title, open and collapsed, equals its listed name.

Lesson for future models

A name typed at every place it's used drifts apart, one build at a time. Each copy was right the day it was written, then a card got renamed and only some copies followed. Name each card once, in one list, and refer to it by key everywhere, error-code text included. Then add a check that fails when someone types the name by hand again. Also, a ${...} inside a single-quoted JavaScript string is printed literally. If that string also contains a quote, the whole script stops with a syntax error. Use backticks. (LESSON #42.)
