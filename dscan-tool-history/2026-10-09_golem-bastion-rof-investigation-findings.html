Golem / Bastion RoF Ratio — Investigation Findings

2026-10-09 · Open item #1 (bug #15b): Golem (torpedo Marauder) lands ~4.8% low vs the clean 2.0x Bastion rate-of-fire ratio every turret Marauder hits exactly. This session's investigation into that gap, following the project's standing rule to verify against primary sources rather than guess.

Result

STILL OPEN No fix was made. The stale hypothesis this item was logged under is disproven (see below), but the actual numeric gap's cause could not be pinned down with primary-source rigor, so nothing was guessed into the code.

What was disproven

Old theory

"Golem's own intrinsic Marauder cruise/torpedo damage role bonus (effect 4635, attribute 1268) is unmodeled — adding it might close the gap."

What's actually true

DISPROVEN The live tool's SHIP_ROLE_BONUS table already has "28710":[["missile","damage",100]] for Golem — a correct, complete model of effect 4635 (confirmed live: eliteBonusMaraudersCruiseAndTorpedoDamageRole1, 8 modifiers all sourced from attribute 1268=100, which everef.net's own rendered Traits page confirms in plain English as Golem's Role Bonus: "100% bonus to Heavy Missiles, Cruise Missiles and Torpedoes damage", unrestricted by damage type). This part of the open item's premise was simply wrong.

Cross-checked all 4 Marauders to find the real pattern

Fetched each hull's full live ESI dogma_effects list and resolved every effect id to its name/modifiers. The asymmetry in the table turns out to be correct, not a bug:

HullTable entriesReal mechanism
Paladin (energy)[25, 100]25% = Energy Weapon skill, 5%/lvl · 100% = flat Role Bonus

Everef.net's own Traits text for Golem lists its per-level bonuses as 10% Cruise/Torpedo max velocity, 5% explosion velocity, 7.5% Shield Operation, 10% Target Painting effectiveness — no per-level damage bonus anywhere. Unlike the three turret Marauders, Golem genuinely only gets the flat 100% Role Bonus. The table's single entry for Golem is already complete and correct.

Checked Bastion Module I's complete effect for a hidden missile bonus

Pulled effect 6658 (moduleBonusBastionModule) in full — every one of its ~45 modifiers, not just the RoF pair already modeled. Found resistance bonuses, scan-strength bonuses, shield-boost-amount, cap-need, turret range and missile-velocity bonuses — nothing that adds extra missile damage beyond the already-modeled -50% cycle time. The module's own description even calls out a specific missile-launcher exception ("Rapid Heavy Missile Launchers are not affected by bastion modules") that doesn't apply to Golem's ordinary Torpedo Launcher IIs.

Hand-derivation against the real killmail — confirms no implementation bug

Using the golden fit's own real ESI data (killmail 138991664: 4x Torpedo Launcher II / Inferno Javelin Torpedo, 3x Republic Fleet Ballistic Control System, Bastion active), ran the exact formula the code uses by hand:

perShot = 405 (raw therm dmg) × dmgSkillMult(3.634) = 1471.9
effectiveCycleSec = 14.4s × rofSkillMult(0.2597) = 3.740s
dps/launcher = 1471.9 / 3.740 = 393.6 → ×4 launchers = 1574.4

That's an exact match to the tool's own sandboxed output (dpsFixed: 1574) — confirming every already-modeled piece is wired together correctly. Pyfa's quoted figure for this fit is 1654, a gap of ~4.8% (equivalently, the fit would need its raw charge damage, or its effective cycle time, to differ by ~5.06% to reconcile).

Where this leaves the gap

VERIFIED CORRECT Golem's role bonus modeling, all 4 Marauders' table entries, all 5 missile skill constants, Bastion's full effect list, and the formula's own arithmetic.

UNRESOLVED The ~4.8% gap against pyfa's reported 1654 DPS. Every mechanism visible through live ESI/everef.net has now been checked and found either correct-as-modeled or not applicable. Consistent with this project's standing rule never to implement a fix as a guess, this item stays open — the memory writeup has been corrected to drop the disproven "unmodeled role bonus" theory and record what's actually been ruled out, so a future session doesn't retread this same ground.
