What changed

  • New PYFA CORE section resist-calc, replacing rah-sim. It has two parts:
    • Tables generated by tools/gen_resist_table.py: RESIST_EFFECTS (124 effects, 308 rows: hull, module, charge and mode handlers with operation and stacking group), RESIST_SKILL_MODULE_ROWS (Compensation skills), RESIST_ATTRS and MODE_ITEMS.
    • Functions:
      • pyfaModPool, pyfaModAdd and pyfaModValue calculate an attribute the way pyfa does: a forced value wins, otherwise base × unpenalized × each stacking group on its own, then the max cap.
      • pyfaModuleResistAttr applies skills, scripts and Assault Damage Control forces to the module before its effects read it.
      • pyfaRahAverage is Effect4928 ported line for line.
  • Engine: the hand pooling (hardener list, Damage Control / Bastion layers, Compensation constant, hull table, Defense Mode table, 3% floor) is replaced by one pass over the hull, the selected mode and every fitted module copy in its state. The Reactive Armor Hardener runs last. The result now includes unrounded resonance values.
  • Retired: SHIP_RESIST_BONUS, simulateReactiveArmorHardener, MAX_COMPENSATION_SKILL use, and the Defense resist values in TACTICAL_DESTROYER_MODE_BONUS.
  • The methodology note on the page now describes the resistance rules as they are.
  • Tooling:
    • pyfa_fit_oracle.py, independent_checks/golden_oracle.py, check_resists.py
    • compare_resists.py, run in the update-check chain; it must print 0 differences
    • regression_suite/dump_results.mjs

Found along the way: modes (correction to Phase 1)

pyfa always gives a Tactical Destroyer or the Anhinga a mode, by default the first mode item. The Anhinga's Primary Mode cuts cruise, torpedo and rapid heavy launcher cycle time to 0.75 (×1.333 DPS); its Secondary Mode halves it. Phase 1 ran only hull and subsystem handlers, so it concluded "no RoF bonus". The Anhinga golden fit (33 DPS) is pyfa's number without a mode; pyfa's default would show about 43. The Skua has no mode selector either. Both are in DEVIATIONS.md and the backlog (Modes). The new MODE_ITEMS table already lists all six hulls with modes.

Not changed (in DEVIATIONS.md)

  • A killmail's low-slot charges aren't paired with their module, so a Capital Flex Armor Hardener's script is ignored.
  • Overheating, effect beacons, implants and boosters.
  • Turret and missile damage-module stacking still uses the rounded table.

Lesson for future models

  • A PYFA CORE lock proves a section hasn't changed, not that it was ever right. Compare a "port" line by line with the pyfa function before locking it (LESSON #25).
  • Don't rebuild pyfa's attribute bookkeeping per module type. Generate handler rows and compute attributes the way modifiedAttributeDict does.
  • pyfa runs more carriers than hulls and modules: skills, charges, and the ship's mode (LESSON #26).
