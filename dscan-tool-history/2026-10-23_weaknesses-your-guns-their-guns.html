How it works

  • wpCandidates(f) runs the engine once per "round". Round k loads each weapon type's k-th untried charge into every active copy, and flies the k-th drone type. Charges change only their own weapon and drones only themselves, so one run serves them all. The results are cached per estimate object: a module-state change makes a new estimate and a new set of runs, while a slider move only re-ranks. The Hecate / Vexor pair takes about 0.3 s in the browser.
  • wpRank evaluates each candidate with the strip's own functions (mysFight, dmgTypedPoint, ttkSeconds).
  • wpFill is called from mysRenderStrip, so every strip refresh refreshes the picks. That covers slider moves, the switch, loss tabs and state changes.

Lesson for future models

Before you rank anything, write down what the ranking is for, and check that the number you sort by contains every input that decides it. The first build sorted charges by applied DPS, which is pyfa's damage-graph number, and that graph ignores the target's resists by default. A card called "Weaknesses" then picked the wrong damage type in 204 of the checked fights. Show pyfa's number, but sort by the quantity that answers the question. Then add a mutation that sorts by the naive number, and make sure the check fails on it (LESSONS_LEARNED #40).
