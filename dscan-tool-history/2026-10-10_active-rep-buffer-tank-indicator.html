Active Rep / Buffer Tank indicator

Date: 2026-10-10   Status: Delivered, verified via 28/28 regression PASS + a 12-case classification unit test (including the real naming trap it was built to avoid) + real-Chromium render check

Requested by the owner: "another helpful indicator would be whether they are active rep or buffer fit" -- asked alongside two related follow-ups (effective range/falloff, and the DPS required to break a tank), with explicit instruction to build the rep/buffer badge first before tackling the other two.

Verification before writing code

This project's standing rule is to verify against primary sources, not assume naming symmetry -- which caught a real trap here. Checked everef.net live (this sandbox has no direct ESI/web access, so done through the linked desktop's own browser) for the actual ESI/SDE group names of every local (self) repair module and its remote (fleet-mate-repairing) counterpart: Shield Booster / Remote Shield Booster, Armor Repair Unit / Remote Armor Repairer (plus Ancillary Armor Repairer / Ancillary Remote Armor Repairer), and Hull Repair Unit / Remote Hull Repairer. The real finding: Ancillary Remote Armor Repairer does NOT start with the word "Remote" -- it starts with "Ancillary." A naive startsWith('remote') exclusion check would have silently misclassified a logistics ship's ancillary remote rep as a self active-armor-rep. Using a substring .includes('remote') check instead (same idiom already used throughout this file for group-name classification) catches it regardless of word position.

The change

Inside the same per-item classification loop that already flags Afterburner/MWD and resist mods (zero new ESI calls -- these items were already being fetched), each item's group name is now also checked against the verified local-repair group names, with the remote variants explicitly excluded. Produces a new tankStyle: {shield, armor, hull} field on the estimate -- presence only, same scope as the Propulsion badge, not yet a repair rate/amount. Rendered as a new line inside the existing Tank Type highlight box: an "ACTIVE REP" badge naming which layer(s) carry a repair module when one is fitted, or a quiet "buffer tank -- no active repair module fitted" line otherwise.
