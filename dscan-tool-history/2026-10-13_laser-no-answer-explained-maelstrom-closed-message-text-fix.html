Rorqual: verified, not a bug (with a correction)

Pulled the Rorqual's real base shield resistances and both hardeners' real resist-bonus magnitudes live (direct ESI blocked this session by org network policy, same as earlier Rorqual work today -- everef.net used as the grounded alternate source): Pith X-Type EM Shield Hardener gives -63.5% EM resist only; Pithum C-Type Multispectrum Shield Hardener (x2 fitted) gives -36.56% to all four types each.

Self-caught correction: the first pass at this (relayed to the owner in chat) read the Rorqual's raw ESI attribute dump directly and asked a small model to guess which attribute_id was which damage type -- it swapped Thermal (274) and Explosive (272), giving a wrong base resist read (Thermal 50%/Explosive 20%) and leading to a wrong specific answer (stated weakest=Explosive, 2nd=Kinetic). Cross-checking against this tool's OWN already-verified SHIELD_ATTR mapping ({em:271, exp:272, kin:273, therm:274} -- tested across 94 golden fits, authoritative) and independently re-fetching the Maelstrom's resists from everef's own rendered page (not a raw attribute guess) both point to the real universal shield baseline: EM 0%, Thermal 20%, Kinetic 40%, Explosive 50% -- the opposite of what was first reported for Explosive/Thermal. Redone with the correct baseline, the Rorqual's actual post-hardener weakest pair is Thermal (≈65%) and Kinetic (≈74%), not Explosive/Kinetic. The bottom-line conclusion doesn't change -- neither Thermal nor Kinetic is a damage type lasers can produce, so "No answer" is still correct -- but the specific numbers given to the owner in chat were wrong and are corrected here for the record.

Lasers (Frequency Crystals) can only ever deal EM and Thermal damage in EVE, and per TURRET_RECS's own live-verified data, laser is never the PUREST answer for Thermal even when Thermal is the target (Multifrequency, the most Thermal-leaning named tier, is still EM-majority) -- so Thermal lands as null in that table, same as Kinetic and Explosive. With this fit's weakest+2nd-weakest both outside EM, buildTurretRecs() correctly returns no laser answer at all.

Backlog item closed -- not a bug, confirmed via live data, same root cause as the Rorqual.
