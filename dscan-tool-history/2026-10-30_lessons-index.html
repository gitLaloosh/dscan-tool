An index for the lessons

ProcessDocs 2026-10-30 · page unchanged (v2026.10.30.1)

The owner asked: "given the size of our lessons learned at this point, how much work is that for an agent? ... is it all still relevant?" LESSONS_LEARNED.md had grown to about 131 KB (roughly 33,000 tokens) and 104 entries.

It was organized by calculation phase, but the newer page, Intel and process lessons had been slotted in among them, mostly under "Phase 2". Two entries (#98, #99) recommended a fix that #102 later overturned.

What changed

  • An Index at the top: one line per entry, grouped by task. The groups are calculation sources; expected values and fixtures; implementing; the page; checks and test machinery; Intel and live data; and delivery, privacy and the repository. It is about 9 KB, so an agent reads the Index (about 2,500 tokens) and opens only the entries that apply. A page or Intel change no longer needs the calculation lessons.
  • Superseded entries marked at their top and in the Index: #98 and #99 (read-ahead past "missing" kill numbers) are superseded by #102. #89 and #93 are noted as partly outdated. Entries keep their permanent numbers and places (// LESSON #n comments point at them).
  • LESSON #101 restored. It was lost when v2026.10.29.8 was delivered from a work tree that didn't have it. The new check would have caught that.
  • New tools/check_lessons_index.py (a chain step, 49 now). It fails when:
    • an entry is missing from the Index or listed twice;
    • the Index names a number with no entry;
    • a number is shared or skipped;
    • an Index line no longer matches its entry's title.
    Four mutations each fail.
  • CLAUDE.md: read the Index first; a new lesson gets an Index line; a lesson a later one overturns stays, marked superseded.

Lesson for future models

None new. The restored #101 is the evidence for this change: a file every delivery appends to can lose an entry without anyone noticing, unless something checks it.
