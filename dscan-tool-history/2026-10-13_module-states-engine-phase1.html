Module states: engine (plan Phase 1)

FeatureBug fix 2026-10-13 · v2026.10.13.19 → v2026.10.13.20 · the owner: "D1: both D2: yes D3: yes D4: Later (when we've learned enough to make a recommendation) D5: not now but make sure it's in the backlog."

What changed

Every fitted module now has a state, as in pyfa: offline, online or active. Overheating isn't modeled (D5, in the backlog). A module's bonuses apply only in the state that turns them on, and only active modules use capacitor. There's no UI for changing states yet; that's Phase 2. The engine already accepts states (a new optional 7th argument to estimateHpAndDps()), and the regression suite uses them.

  • pyfa's rules (eos/saveddata/module.py):
    • An offline effect always applies, a passive one when online or active, and an active one only when active. A loaded charge's effects follow its module's state.
    • A module can be active only if it has an active effect and nothing blocks it. Bastion blocks MJDs, a Networked Sensor Array blocks capital MJDs, a Zero-Point Mass Entangler blocks MWDs, and a Disruptive Lance blocks cloaks.
    • Group limits: maxGroupActive / maxGroupOnline. One propulsion module active at a time. One Command Burst online and active, plus maxGangModules on command ships and with a Command Processor. A FAX can have only one Capacitor Booster online.
    • Subsystems are always online. Rigs are too in this tool (they can't be offlined in EVE; pyfa lets you).
  • Generated tables (tools/gen_module_state_tables.py, which runs pyfa's handlers):
    • EFFECT_STATE_TYPE: 122 effects (99 active, 4 offline, 19 overheat)
    • GROUP_LIMIT_MOD_EFFECTS: 8 effects
    • ACTIVATION_BLOCK_EFFECTS: 4 effects
  • Default states (killmails, d-scan, EFT pastes): the best case the game allows. Every module that can run is active, within the group limits; for propulsion, the fastest one is active. The siege family defaults to active (D2). These default to online:
    • cloaks, MJD/MJFG, the Signature Suppressor burst and Entosis Links (D3)
    • my call, kept as before: Capital Sensor Arrays and the Assault Damage Control burst. The tool already treated their active effects as not running, and the ADC burst is short with a long reactivation delay, the same reasoning as D3. The ADC's passive Damage Control resists still apply when online.
  • New engine behavior: the Assault Damage Control's active burst (pyfa Effect7012: all its resonances forced to 0.25) is now modeled when a state sets it active.
  • State format: {typeId: 'offline'|'online'|'active'} or copy counts {typeId: {active, online, offline}}. Copies of one type are interchangeable. Weapons hand their active copies to High slots in flag order. A request that breaks a rule is refused with a reason, which the Phase 2 UI will show on hover.
  • Result: result.moduleStates = {items, refused, assumed}, giving each fitted type's copies per state, the reasons for any defaults or demotions, and any refusals.
  • Text: the methodology note explains the assumed states. Capacitor captions now say "every running module".

Lesson for future models

A module-state gate that counts each module once ("active copies if it can be activated, else online copies") is wrong for modules that carry both a passive and an active effect. Examples are the Assault Damage Control, Signature Suppressor, Interdiction Nullifier, Warp Core Stabilizer, Entosis Link and the MWD's capacity penalty. A Signature Suppressor left online would lose its passive −10% signature. This was found before coding by listing every module with mixed handler types. The code now counts per effect (effQty(dt, effectId)). See LESSONS_LEARNED.md #17.

Found along the way (not changed)

REQUIRED_SKILL_ATTRS in index.html lists requiredSkill1–3 only, while pyfa's requiresSkill() checks 1–6 (LESSONS #15). In the SDE, four capital T2 weapons carry their Gunnery / Missile Launcher Operation requirement in slot 4:

  • Quad Mega Pulse Laser II
  • Triple Neutron Blaster Cannon II
  • Quad 800mm Repeating Cannon II
  • Rapid Torpedo Launcher II

So Gunnery-gated bonuses (e.g. Controlled Bursts) may be missing on those weapons. This is logged in the backlog for a check.
