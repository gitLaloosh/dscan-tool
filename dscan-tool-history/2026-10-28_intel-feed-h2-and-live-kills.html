What you get

  • Kills that arrive.
    • The page finds the newest kill itself. From sequence.json's number it steps 64, 128, 256 ... ahead until a file is missing, then halves the gap. That's about 15-20 requests, at least 80 ms apart.
    • It reads back the 240 before the newest in batches: requests start 80 ms apart, and it doesn't wait for each answer. That takes about 20 s; one at a time took a minute or more.
    • A missing or blocked file means "not there yet". The page checks sequence.json and waits 6 s with no note. INTEL-05 shows only when sequence.json fails too.
    • If the kills it reads were uploaded over an hour ago (a sleeping tab), it finds the newest again, at most once every 5 minutes.
  • The H2 look, on the Feed and Near You:
    • Each row sits on a quiet panel, with no borders, pills or rules between rows.
    • Pilots and ships sit on quiet tags (ships in a cooler fill); keywords are in small caps.

  • The line as typed: a small chevron at the right of each report opens a strip along the bottom. It shows who sent the line, the line and the channel, plus the copy-shape button (moved here). It stays open through redraws.
  • Security colours: the system name in EVE's colour for its tenth, from 1.0 to 0.0 and below. A security above 0.0 but under 0.05 shows as 0.1 (low-sec); v.99 called it null. The system's title gives its security.

Lesson for future models

LESSON #89: before writing the test double for a live service, read its edges from the page's real origin: the missing item, the end of the list, any index it publishes, the headers on an error. Then build the double from what came back, and know what the double itself skips. Playwright's route.fulfill() is never CORS-checked, so a response the real browser blocks must be an aborted request in the double. v.99's double sent a header-less 404 that the page read as a plain 404, so it could never show the real failure. My first v.100 double did the same; a mutant that treats a network error as "feed down" passed until I changed it to abort. In the happy path, also check that the error note is absent: a check that only bounds a delay ("nothing for 6 s after a 404") still passes when the page is failing slowly.
