Passive shield recharge modeled + "Break Point" wording

2026-10-12 · index.html · from the architecture backlog ("Passive shield recharge has no equivalent to the capacitor-stability feature") · Erik: "is passive shield recharge accounted for in our dps to break tank calculations?" -> "ok, let's work on that next" -> "rather than using the phrase 'needs >X DPS' to just say 'Break Point: X'" -> "do what you need to for the calculations then we can discuss the UI"

Finding

Passive shield recharge was entirely unmodeled -- the DPS-to-break-tank figure only ever counted an active Shield Booster's own output, silently understating every shield-tanked fit (and showing NOTHING at all for a pure-buffer shield fit with no booster, even though every ship regens shield passively). Confirmed the real EVE formula directly against pyfa's own source (eos/saveddata/fit.py, calculateShieldRecharge()): rate(x) = 10×√x×(1−√x)×capacity/rechargeTimeSec, peaking at x=0.25 (corrected after initially telling Erik 50%) where it collapses to 2.5×capacity/rechargeTimeSec -- the same "2.5×" constant already used by this file's existing capacitor peak-recharge-rate formula, since it's the same universal mechanic applied to a different pool. Also confirmed via pyfa's GUI source (gui/builtinStatsViews/rechargeViewFull.py) that its own 2-row "Reinforced"/"Sustained" layout shows the SAME peak value in both rows for the passive-shield column (the "Reinforced" cell is coded to always stay blank) -- so a single peak number isn't even a simplification relative to what pyfa itself displays.

Fix

New constants: SHIELD_RECHARGE_TIME_ATTR=479, SHIELD_RECHARGE_RATE_MULT_ATTR=134, SHIELD_CAPACITY_MULT_ATTR=146, SHIELD_POWER_RELAY_RECHARGE_ATTR=338, MAX_SHIELD_OPERATION_MULT=0.75. Four new stacking-penalized fraction pools mirror the capacitor side's own (shieldRechargeTimePctFractions, shieldCapacityPctFractions/shieldCapacityBonusFractions split by direction, shieldPowerRelayRechargeFractions kept separate since it's a different real attribute). shieldHP's own finalize line now folds in the attr146 pools -- this is the ship's REAL effective capacity, used everywhere (EHP display, break-tank calcs), not a calc-only side number, so Flux Coil/PDS's capacity effect is now correctly visible in the Resistance card too. Peak passive regen: peakShieldRechargeRate = 2.5 * shieldHP / shieldRechargeTimeSec, where shieldRechargeTimeSec applies MAX_SHIELD_OPERATION_MULT (always, independent of any module) times the two module pools.

tankStyle.shield is now non-null whenever shieldHP > 0 (every ship, module or not) -- shape changed from {sustainedDps} to {activeDps, passiveDps, breakPointDps}, additively combining an active Shield Booster's output with the new passive ceiling. resistanceCardHtml()'s Repairs strip now always shows a Shield row for any fit with shield HP (armor/hull still only show with an active rep fitted, since neither has a passive mechanic). Wording changed per Erik, "needs >X DPS sustained to break" -> "Break Point: X DPS sustained", everywhere (plain active rep, armor+Nanite-burst, and the new shield cases) -- each row got a new sub-line (.repairs-subdetail) breaking out the passive/active components, and a passive-only shield row gets a muted "PASSIVE" badge instead of "ACTIVE REP".
