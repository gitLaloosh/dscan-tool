Mindlink implants on Command Burst strength

Calculation 2026-10-21 · v2026.10.14.27 → v2026.10.14.28 · the owner: "Ok do it", for the open gap listed after v.27 (DEVIATIONS.md: "mindlink implants' Command Burst strength"). Verified against pyfa v2.69.3 (see 2026-10-21_pyfa-2-69-3-update).

What changed

  • A pasted fit's mindlink now strengthens its Command Bursts on the EWAR / Misc card, as in pyfa. Each of pyfa's mindlink handlers does two things for its command type:
    • filteredChargeBoost: the loaded charge's warfareBuffNMultiplier × (1 + mindlinkBonus/100). That is +25% on every mindlink, unpenalized, in the same pool as the Command Specialist skills. This was missing.
    • filteredItemBoost: the burst's buffDuration +25%. This was already applied, so durations don't move.
  • Covered (pyfa effect → implants):
    • 1643 armored, 1644 information, 1645 / 1646 shield and skirmish, 1848 mining foreman;
    • the single-type mindlinks, plus Imperial Navy, Federation Navy, Republic Fleet, Caldari Navy, ORE Mining Director, Guri Malakim and Sisters Expedition (each carries two).
  • Expedition Command Mindlink (Effect12542) already worked: it boosts the burst's own warfareBuffNValue, which the implant table already applied.
  • Killmails (Pilot Analyzer) are unchanged. A ship killmail never lists implants, so none are applied (PILOT_ANALYZER_APPLY_IMPLANTS false).

Why it was missing

gen_implant_table.py tests a charge row's filter on (charge, module) pairs, and its pair list held only weapons and their ammo. All 20 mindlink charge rows were skipped with "filter matches no published item". The fix adds every Command Burst paired with the charges it can load (chargeGroup1-5). The generator now fails if there are no such pairs. pyfa's filter is exactly "the burst requires <X> Command" (asserted). In ewar-calc, pyfaEwarSetup now adds the implant charge rows to the charge-multiplier pool, the same pool the skill rows use (one line). LESSONS_LEARNED #35.

  • A generator's "matches nothing" skip can be a gap in its own test set. Before accepting it, ask whether pyfa applies the row to a real item in game. Here it did: every Command Burst. See LESSONS #35.
