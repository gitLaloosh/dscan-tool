Tactical Destroyer Propulsion Mode bonus — Speed/Align time fix (2026-10-11)

Bug report from Erik: on a Confessor/Hecate/Jackdaw/Svipul, picking "Propulsion Mode" in the UI left the Speed/Align time numbers completely unchanged — identical to Defense or Sharpshooter Mode. Root cause: TACTICAL_DESTROYER_MODE_BONUS's propulsion entry has been deliberately empty since the Tactical Destroyer Mode mechanic first shipped (2026-10-08), on the stated theory that "Propulsion Mode only affects velocity/inertia, which this tool doesn't compute at all." That was true in 2026-10-08. It stopped being true once Speed/Align time was built in a later phase (F3) — nobody circled back to wire Propulsion Mode into it, and the in-app disclosure text kept repeating the stale claim.

A deeper correction, found while researching the fix

The original 2026-10-08 research also concluded "this is a BUILT-IN SHIP ABILITY with no fitted item/type backing it at all." That part was wrong. pyfa/eos's own source code (eos/saveddata/ship.py: Ship.__getModeItems/Ship.modes — "if we have items, then we are in a tactical destroyer and must have a mode"; eos/item/stance.py: "Stance is internal name for tech 3 destroyer tactical modes") shows each mode is a real, separate item type — just an unpublished one, in an ESI group called "Ship Modifiers", matched by eos via name-prefix against the hull's own name (e.g. "Confessor Propulsion Mode"). That's why it never turned up in ESI's /universe/ids search (published entities only) or in the hull's own dogma_effects — those are the two places the original research looked.

Resolved the 12 type ids (4 hulls × 3 modes) via fuzzwork's typeid API (unpublished types aren't searchable by name there either, but fuzzwork's SDE-backed lookup still has them), then read each Propulsion Mode item's own dogma data directly via ESI by numeric id (unpublished types are still readable by direct id lookup, just not by name search). Confirmed dogma operator 5 = PostDiv (final = base / modAttr) by checking the arithmetic against everef.net's published per-hull Propulsion Mode percentages — exact match in all 7 cases:

What changed in dscan-tool.html

  • New TACTICAL_DESTROYER_PROPULSION_BONUS constant (per-hull inertiaBonusPct / propSpeedBoostBonusPct / maxVelocityBonusPct / propCapUseReductionPct, per the table above).
  • baseAgility now folds in the inertia bonus unconditionally when Propulsion Mode is selected — both baseAlignTimeSec and boostedAlignTimeSec derive from it, so align time improves even with no prop mod fitted, matching everef's "while Propulsion Mode is enabled" wording (not conditional on a prop mod running).
  • cruisingSpeed folds in Jackdaw's direct max-velocity bonus.
  • A fitted AB/MWD's own speedFactor (read in the per-module loop) is boosted for Confessor/Hecate/Svipul before it feeds into boostedSpeed.
  • Hecate's cap-use cut is applied specifically to a fitted AB/MWD's own capacitorNeed, scoped to the "propulsion module" group only (never any other cap-using module), before it feeds capDrainPerSec.
  • The stale "Propulsion only affects speed/agility, which this tool doesn't track" line in the in-app "How Tactical Destroyer Mode is handled" disclosure is corrected.

Verification

Ran the actual updated code (sandboxed) for all 4 hulls, with and without a 1MN Afterburner II fitted, in Sharpshooter vs. Propulsion mode. Every ratio matched the predicted bonus exactly: e.g. Confessor's boosted-speed gain over baseline grows by exactly 1.667× (the +66.7% speed-boost factor) going from Sharpshooter to Propulsion mode; Hecate's active cap drain drops to almost exactly 1/3 in Propulsion mode; Jackdaw's cruising speed (with no prop mod at all) goes 225→300 (exactly +33.3%) regardless of mode.

Not yet pyfa-screenshot-confirmed — unlike the EWAR effectiveness bonus work, this one is grounded in eos source code + everef.net's published percentages + internal arithmetic cross-checks, not a side-by-side pyfa comparison. If Erik wants the same screenshot gate used for prior calculation changes, a Confessor/Hecate/Jackdaw/Svipul fit with an AB or MWD, toggled to Propulsion Mode in pyfa, would confirm it.
