Renamed Threat Vector, moving to threatvector.space

PageExtension 2026-11-05 · v2026.11.05.1

Why

  • Build queue 013, Project doc roadmap/threatvector-move-plan.md. The owner (2026-11-04) registered threatvector.space and chose to rename the tool in the same move ("Rename in the same move (Recommended)"), the repository too ("I'd like it to be threatvector rather than dscan-tool"). From the mockup he picked title B and tagline B. Saved data: "Users re-enter it". Footer: "Write the repo link in (Recommended)".
  • His steps on GitHub and Cloudflare are in two Project docs written for this move: a checklist and a timeline of the waits.

What changed

  • The page: the tab title "Threat Vector · EVE Online threat assessment", the name "Threat Vector", the line "For EVE Online: who's in system, what they fly, and how to beat them." The footer's first line names Threat Vector and links the source at github.com/gitLaloosh/threatvector, written in. siteSrc, which built that link from a github.io address, is gone: the page's own domain has no account name to read.
  • CNAME at the root, threatvector.space. Merging is the moment the site moves, so the owner's DNS steps come first.
  • The extension, 1.1.0: "Threat Vector for zKillboard" (short name "Threat Vector"), its menus "… in Threat Vector", the default address https://threatvector.space/. Someone who pressed Save before has the old default stored; it now opens the new address, and the options page shows the new one. Any other saved address (a local copy) is kept.
  • Repository text: NOTICE.md, CLAUDE.md (the address, the repository, the names that stay), tools/README.md, ERRORS.md's intro, and the contact line in the two tools that ask CCP's servers.
  • Unchanged on purpose: every localStorage key (dscan…), the IndexedDB databases (dscan-tool-cache, eta-intel, dscan-intel-sounds), the extension's eta-* menu IDs, dscan-tool-history/. Browsers keep each address's saved data apart, so the new address starts empty either way; renaming the keys would only add churn.

Stored data, both ways

  • No key or store changes, so upgrading and reverting read the same data as before. At the new address storage starts empty (the owner's choice: users re-enter their data).

Checks

  • header_check.py: the new title, name and tagline at 1440, 375 and 320 px; the footer's written-in link and no #siteSrc; CNAME exactly threatvector.space and a newline. Five mutants, each caught: the old title, the old tagline, the span left behind, the link pointing at the old repository, CNAME without its newline.
  • extension_check.py: the manifest's name, short name and version; every menu title; the new default; the old default stored opens and shows the new address. Four mutants, each caught: the old default, no mapping in the background, none in the options page, an old menu title.
