Backlog #1: T3 Strategic Cruiser Propulsion subsystem speed/agility bonus

2026-10-11 · dscan-tool.html · "T3 subsystem speed/agility excluded -- the Speed/Align card reads only hull-level attributes + Tactical Destroyer Propulsion Mode bonuses, with zero consideration of fitted T3 Propulsion subsystems" (backlog item's own framing; a prior v1 pass had explicitly flagged and deferred this exact gap, see below)

What the real mechanism is (live-ESI-verified, not guessed)

Fetched live dogma data for all 12 Propulsion Subsystem types (ESI group 957) across all 4 T3 races, plus the 4 race-specific "<Race> Propulsion Systems" skills. Each race's "speed+agility" variant (Legion/Loki "Intercalated Nanofibers", Tengu "Chassis Optimization", Proteus "Hyperspatial Optimization") carries two flat per-level container attributes -- a maxVelocity-bonus one and an agility-bonus one -- but their value as given by /universe/types/{id} is only the PER-LEVEL magnitude. The actual scaling happens on the race's own Propulsion skill ITEM (not the subsystem), via a LocationGroupModifier/domain shipID/operator 0 effect:

This exact "container attribute, value actually scaled by a SEPARATE skill effect, not the subsystem's own effect list" trap had already caught one bug in this file (SUBSYSTEM_EWAR_BONUS's Tengu/Proteus Core subsystems, fixed earlier this project). It applies here too -- re-checked individually for all 4 races rather than assumed, since the first provisional pass (before this re-check) wrongly treated these as flat, unscaled +/-5% ItemModifiers.

The confirmed Proteus asymmetry

Proteus's own in-game description for Hyperspatial Optimization literally says "improves the agility and warp speed" -- and live ESI confirms it is NOT a drop-in replacement for the other 3 races' maxVelocity+agility subsystem. It cuts agility by -37.5%@V same as Tengu, but has zero effect on maxVelocity -- instead granting +50%@V to warpSpeedMultiplier (attribute 1440), a stat this tool doesn't model anywhere (no warp-speed figure exists in the Speed/Align card at all). This is disclosed as an explicit out-of-scope gap, not silently dropped or incorrectly folded into the maxVelocity bonus.

Deliberately excluded subsystems (checked, not just assumed irrelevant)

  • "Interdiction Nullifier" (45610/45613/45616/45619, all 4 races): no speed/agility effect at all -- confirmed for Loki's 45619, whose own container attribute instead feeds a warp-capacitor-need mechanic (effect 6927), unrelated to maxVelocity/agility.
  • The 3rd variant per race -- "Wake Limiter" (Legion 45612, Loki 45621), "Fuel Catalyst" (Tengu 45615), "Localized Injectors" (Proteus 45618): also confirmed not to touch maxVelocity/agility directly. Legion's/Loki's Wake Limiter instead boosts a FITTED prop mod's own speedFactor AND reduces a fitted MWD's own sig-bloom -- the same mechanism CLASS as backlog #10's Interceptor fix, but scoped to "this subsystem fitted" rather than "this hull group". Tengu's Fuel Catalyst instead grants an overheat-tolerance bonus -- a runtime-state-dependent mechanic, same out-of-scope class as Tactical Destroyer Modes. These are a disclosed, deliberately deferred separate gap, not part of this fix.

Also debunked, in passing, a mistaken claim in the old v1 "flagged gap" comment: it suspected Loki's Offensive subsystem (Support Processor, 45609) "also touches these attributes" because it carries an attribute numerically adjacent to the real propulsion-bonus attributes. Live ESI confirms the effect that actually consumes it (4290) targets capacitor-need for remote reps, nothing to do with maxVelocity/agility -- a reminder to check the effect's actual modified_attribute_id, not just attribute-id proximity.

The fix

Added SUBSYSTEM_SPEED_AGILITY_BONUS, keyed by stringified Propulsion subsystem type id → {maxVelocityPct, agilityPct} (both already expressed at max-skill-V, this file's standing convention). A new subsystemSpeedAgilityBonus reduce sums across whichever subsystem(s) are actually fitted (0/0 for anything off-table or non-T3), folded into baseAgility/cruisingSpeed as one more independent multiplicative layer -- same "no stacking penalty between a ship/subsystem bonus and a module bonus" convention already used for every other hull-level bonus in those two formulas.
