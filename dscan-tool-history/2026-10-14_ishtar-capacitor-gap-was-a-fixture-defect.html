Ishtar capacitor gap was a test-fixture defect

Test suiteClosed gap 2026-10-14 · index.html unchanged (still v2026.10.14.1) · the owner: "did you still need a screen shot from the ishtar fit? if so, send me the eft"

What was wrong

The ishtar_zkb137694046 golden fit (a real loss, zKill 137694046) said capacitor stable 96.9%. The owner's pyfa screenshot of the same fit said 40.5%. The gap had been blamed on the capacitor model: first the closed form, then on inputs once v2026.10.14.1 made the simulator match pyfa exactly.

Preparing the EFT for a fresh screenshot, I ran the fit as an EFT paste, which loads full game-data records. That run gave stable 40.5%, exactly pyfa.

The cause was the fixture: it had no group record (40, Shield Booster) for the X-Large C5-L Compact Shield Booster. Without it, the engine dropped the booster entirely, so the pinned drain was only the two hardeners (5.2 GJ/s). The live page fetches the group from ESI, so the tool itself was already right. Only the test was wrong.

Fix

  • Added the real group record to the fixture: one text insertion, the rest of golden_fits.json is byte-identical.
  • New guard in run_regression.mjs: any fitted item, drone or fighter whose type or group record is missing from its fixture now fails the suite. Cargo and fleet hangar items are exempt. Of all 161 fits, only this one had a fitted-item gap. The Leshak killmail is missing cargo records only.

Verification

  • Independent: tools/independent_checks/check_cap_sim.py gained an Ishtar case. It builds the fit by hand from SDE values and runs pyfa's own capSim.py: capacity 2,576, drain 77.20, net +7.12, stable 40.5%, booster 119.2 HP/s.
    • Drain = booster 400 GJ × 0.9 (Shield Compensation V) / 5 s + hardeners 3.2 + 2.0.
    • Capacity = (1,400 + battery) × Capacitor Management × both Flux Coils, unpenalized.
  • Fail-then-pass: the old fixture fails the new pins and the new completeness check; the fixed fixture passes.
  • Suites: 161/161 pass; parse tests 280/280; compare_cap_sim.mjs 483 simulations, 0 mismatches against pyfa.

Lesson for future models

When the tool disagrees with pyfa on one fixture, run the same fit as an EFT paste, which loads full records, before blaming the model. A trimmed fixture can drop a whole module silently, and a missing group record does that just as surely as a missing type. Two changes to the capacitor model were weighed partly against this fit's gap, which was never the model's. See LESSONS_LEARNED.md #6.
