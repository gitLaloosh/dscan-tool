Scope

The full backlog item covered D-Scan Analyzer, Pilot Analyzer, and Fit Analyzer. [stated] asked for the Pilot Analyzer tab only this round -- the other two tabs' inputs (dscanInput, fitAnalyzerInput) are untouched and still only insert a newline on Enter, as before.

Implementation

Pilot Analyzer has two relevant inputs, both single-line <input type="text"> (the third control, shipSelect, is a <select> and was left alone -- Enter on a dropdown has its own native/inconsistent behavior and wasn't part of the ask):

  • #pilotName
  • #manualShip

A keydown listener on each calls document.getElementById('fitBtn').click() on Enter (after preventDefault()). Deliberately triggers the real button's click() rather than calling runFitCheck() directly: runFitCheck already sets btn.disabled = true while a pilot lookup is in flight, and a disabled <button> never dispatches a click event -- so this inherits the existing in-flight guard for free, no duplicate logic needed.
