Missile T2 ammo tiers + applied-DPS metric correction

2026-10-12 · dscan-tool.html · follow-up to the 2026-10-11 missile damage-application-efficiency feature, raised by Erik: "are we excluding T2 ammo from the calculations?" then "I'd imagine precision would likely have a higher chance to apply damage in many cases... we're looking for better applied DPS over time, right?"

The correction

Erik's own catch, not a bug report: ranking ammo by application percentage alone is not the same as ranking by actual damage dealt over time. Precision-tier ammo buys a higher application % specifically by cutting its own raw damage -- a naive "best application %" pick can recommend an ammo that lands more often but deals less total damage than an alternative with lower application. This was already a latent gap in the 2026-10-11 T1-only release (Rocket vs. Torpedo application % was never a fair comparison without each class's own raw damage and cycle time), not something newly introduced by adding T2 -- T2 just made it obviously wrong, since Precision's entire design purpose is trading damage for application.

New metric: appliedDps = (per-shot damage / launcher cycle time) x applicationFraction. Confirmed with Erik: within one launcher class, every tier shares the same launcher, so cycle time cancels out of a tier-vs-tier comparison -- ranking by (damage x application) alone is mathematically sufficient there, no new data needed beyond what T1 already fetched. Across classes, cycle time genuinely differs (a Rocket Launcher cycles far faster than a Torpedo Launcher), so a true applied-DPS comparison needs each class's own reference launcher's rate of fire too -- this was the scope Erik explicitly approved extending into.

Revert switch, per Erik's request: MISSILE_REC_METRIC = 'appliedDps' (one constant, every ranking call site reads it). Setting it to 'applicationPct' reverts to the pre-2026-10-12 behavior with a one-line change -- confirmed via a throwaway-copy revert test (see Verification below).

Flagged for later, per Erik's request: revisit this metric choice in more depth, possibly with an independent Opus-model review. Not urgent, logged so it isn't forgotten.

T2 ammo coverage (grounded live, not assumed)

Checked via ESI's /universe/ids/ name resolution rather than assumed symmetric: T2 tiers exist for Rocket (Rage/Javelin), Light Missile (Fury/Precision), Heavy Missile (Fury/Precision), and Cruise Missile (Fury/Precision). Torpedo and Heavy Assault Missile have no T2 tiers at all -- every T2-name candidate for those two classes returned no match. Confirmed (same "identical mechanics across damage types" discovery as the T1-only pass, spot-checked on a 2nd race) that a T2 tier's own explosion mechanics and damage are identical across all 4 racial damage-type variants of that class+tier, so one reference id per (class, tier) -- 14 total, not 56 -- covers every damage-type recommendation. 6 reference T2-launcher ids (one per class) were also fetched live for their rate of fire (RATE_OF_FIRE_ATTR=51, already an established constant in this file).

Implementation

MISSILE_CLASS_REFERENCE_AMMO (6 class-only ids) replaced by MISSILE_AMMO_CATALOG (class -> {launcherTypeId, tiers: {tierName -> ammoTypeId}}), 14 ammo ids + 6 launcher ids, all still live-fetched via the existing getType()/IndexedDB pipeline (ARCH-1 avoidance unchanged). rankMissileClasses() renamed rankMissileAmmo(), now flat-maps every (class, tier) combination, computes rawDps (summed DAMAGE_DEALT_ATTR / launcher cycle seconds) once per entry, and sorts by MISSILE_REC_METRIC. Each entry's label field renamed name and now carries the tier (e.g. "Precision Light Missile", not just "Light Missile"), following EVE's own naming convention (confirmed live: T1 = "<race name> <class>", T2 = "<race name> <tier> <class>"). missileRecTileHtml() updated for the renamed field. run_regression.mjs's flattening block renamed to match (missileBestClass* -> missileBest*) and gained *AppliedDps fields.
