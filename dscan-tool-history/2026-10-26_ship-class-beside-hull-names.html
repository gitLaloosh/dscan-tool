A hull's ship class beside its name

FeatureTests 2026-10-26 · v2026.10.14.73 → v2026.10.14.74.

Backlog item (the owner via the inbox): "need to add something to tell the user what class a hull is in. if they dont know the hulls from memory, knowing the ship class would be nice." From a mockup of the real page with two options, the owner picked "A: beside every name".

What you see

The hull's class is shown in muted text right after its name. The class is the game's group name: Strategic Cruiser, Combat Recon Ship, Heavy Interdiction Cruiser, Battleship. The D-Scan cards and the My Ships list already showed it.

  • Pilot Analyzer:
    • the hull button ("Loki Strategic Cruiser · 2 of 5 losses") and every row of the hull menu;
    • the Last Kill line, for both ships ("Vedmak Cruiser · 9/1/2026 · Curse Combat Recon Ship");
    • the attackers' ships in the Last Kill panel, as a hover (that column has no room).
  • Fit Analyzer: the name line ("Megathron Battleship — Battleship target") and the "Viewing my ship" banner.
  • The Matchup board: the threat, your ship, and the rows of your ship menu.
  • Narrow screens: the hull button and the menu rows stay on one line; on the narrowest phones a long class in the button is cut with "…" (the menu shows it whole).

How it works

  • Written at once when it's known: hullClassHtml(typeId) writes the class straight away when the hull's type and group are already loaded, which they are for the hull being assessed.
  • Otherwise filled in later: for other hulls (the rest of the hull menu, a last kill's ships), fillHullClasses looks them up after the page changes. This uses the same type and group cache as everything else, including the 7-day IndexedDB cache.
  • A lookup that fails leaves the class out; the name is still there, with no error.
  • Screen readers and copying: the name and the class are two words.
  • No calculation changed.

Lesson for future models

LESSON #60, extended. The board draws your ship's name twice: an invisible twin in the button keeps the size, and the menu is drawn on top of it.

  • The class added inside the twin is a span with its own colour. color:transparent on a parent doesn't reach a child that sets its own colour, so on a phone the class showed twice.
  • Anything new inside a hidden twin needs its own transparent rule. The check reads its computed colour.
