Golden-fit data refresh from the SDE

Test suiteTooling 2026-10-14 · index.html unchanged (v2026.10.14.1) · the owner: "do we need to revisit all of our golden fits or test data at some point if it's been tainted by old code making stuff up?", then "tell me what you're going to work on next and we'll get started"

Why

The Ishtar capacitor gap turned out to be a trimmed test record (history 2026-10-14_ishtar-capacitor-gap-was-a-fixture-defect.html). A follow-up measurement showed about 20 more fits whose fitted modules lacked attributes the engine reads. Some tests therefore exercised data the live page never sees. The live page always fetches full records from ESI.

Reference data: CCP's SDE as shipped with pyfa v2.69.2, client build 3579973 (2026-10-06). The owner's updated pyfa shows exactly this version and data build, so the tool, its tests and his pyfa now all use the same game data.

What changed

  • New tools/refresh_golden_fixtures.py. For every type a fit references (types, ship, tally including cargo, slot maps, killmail items) it fills in the SDE attributes and effects, plus mass, volume, capacity and radius. It also adds every group record a type points at.
    • It merges: SDE values win, and anything only a live-ESI capture had is kept. That covers 282 attributes (zero placeholders, a Hornet EC-300 range) and one effect (Zirnitra ammo tracking).
    • It keeps the file's compact serialization, and a second run changes nothing.
    • Report mode is the completeness check: 0 of 161 fits change.
  • Totals:
    • 1,925 attributes filled on 194 trimmed records
    • 33 missing types added (Leshak cargo)
    • 2,470 group records added
    • 19 effects added, all on cargo items (boosters, accelerator)
    • one value changed: the Hawk's shipBonusCF 10 → 7.5, the 2026-09-22 patch. Firepower uses the hand table there, so no output moved.

Effect on the tests

15 of 161 fits' outputs moved. Only one pinned check failed: legion_owner capacitor 300 → 2,100. Every other move was in a field those tests never pinned, and each test still checks what its name says.

Lesson for future models

A test fixture is only as faithful as its records. Before trusting a golden fit, or after adding one, run refresh_golden_fixtures.py in report mode; it must print 0 of N fits change. A pin that matched a trimmed record can still pass while every unpinned field is wrong, which is how the Legion's killmail copy computed targeting range 0 and capacitor 300 without failing anything.
