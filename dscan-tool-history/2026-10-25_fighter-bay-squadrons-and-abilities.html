What you see

  • The Fighter bay section of the Fit card works like the drone bay.
    • One square per squadron the hull could have in space of that type (the squadrons in the bay, its tubes and that class's limit). Click to launch, or click the last filled square to take one back.
    • A square the free tubes or class room won't allow is dashed, with the reason (e.g. "all 4 tubes are in use").
    • The heading reads "Tubes 4 / 4 · Light 3 / 3 · Support 1 / 2", with a bar for the tubes.
  • Ability buttons under each type. Each shows the game's own icon and a short name (Attack, Missiles, Bomb, Web, Neut, Point, ECM, MWD, AB, Evasive), lit when on. They come in the order damage, EWAR, propulsion, and each hover says what it does to the numbers.
    • A damage ability switched off adds nothing.
    • A speed ability switched on makes the squadron faster in Damage Application.
    • Support EWAR is "not in the numbers yet (a coming update)".
    • Bombs are disabled for now, with "Bombs are counted in a coming update".
  • The default launch (the owner's "Damage first"): damage squadrons hardest-first within the tubes and class limits, then support squadrons in the tubes left, webs first. A Nidhoggur with Einherji II x24, Dromi II x3 and Siren II x3 puts out 3 Einherji (the light limit), then the Dromi; the Siren waits.
  • Open by default when the hull can launch what the bay holds; collapsed, its row says "4 / 4 tubes".
  • Kept like the other states:
    • the reset button clears it;
    • My Ships stores it (fighterStates);
    • the Pilot Analyzer's losses have it too.
  • Structure fighters in a ship's bay are listed but can't be launched (pyfa: Fighter.fits() is false). Before this version the tool launched one into a free tube.

Where the icons come from

Neither pyfa nor the SDE has fighter ability icons:

  • pyfa's dogma effects carry no iconID;
  • images.evetech.net serves only item icons and renders;
  • the sites that mirror the client's files were blocked from the workspace.

The owner connected his EVE client's shared cache (C:\CCP\EVE) to the session, read only. The new tools/gen_fighter_ability_icons.py reads the client's own data through tq/resfileindex.txt:

  • res:/staticdata/fighterabilitiesbytype.static: per fighter, its ability slots;
  • res:/staticdata/fighterabilities.static: per ability, its iconID;
  • pyfa's iconids.0.json: the icon file.

Both .static files are SQLite. Each slot is mapped to pyfa's ability effect (slot 0 primary, 1 propulsion, 2 secondary). The generator asserts that every ability ID is the same effect on every fighter, and that every ability pyfa implements on all 94 fighters has an icon. Abilities pyfa doesn't implement get no button, as in pyfa: the superiority fighters' tackle, the Shadow's kamikaze and the heavy fighters' MJD.

The output is FIGHTER_ABILITY_ICONS and 26 PNGs in img/fighter-abilities/, copied unchanged. --check needs no client and is in the update-check chain: a fighter added by a game update shows up there.

What pyfa does, and how it's matched

  • Defaults: Fighter.__init__ (already ported as pyfaDefaultFighterAbilities). A support squadron's EWAR and afterburner are on, MWDs and evasive maneuvers off.
  • Active abilities run their handler on their own squadron (Fighter.calculateModifiedAttributes), in their runTime. A grouped effect runs once, otherwise once per fighter.
    • The three speed abilities are grouped.
    • Each boosts maxVelocity by the squadron's own MODIFIED bonus attribute, stacking-penalized in 'default': the same group as Drone Navigation Computers and Capital Drone Speed Augmentors.
    • Evasive maneuvers also changes the squadron's signature and shield resonances, which the damage graph doesn't read.
    The generator parses that from pyfa's source and asserts each part. It writes PROJ_FIGHTER_SELF_EFFECTS and adds the three bonus attributes to the fighter handler table: e.g. the Thanatos's support-fighter afterburner bonus (Effect12594) and the Nidhoggur's support fighter velocity (Effect12890), now recorded because the filters run over every fighter.
  • PYFA CORE projected: pyfaProjFighterSetup takes the squadron's active ability ids and adds those rows to its pools. pyfaProjDroneSetup's attribute function takes an item's own extra rows.
  • Engine: options.fighterStates = {typeId: {n, ab: {effectId: on}}}.
    • Every fighter type in the bay is listed in estimate.fighterStates.
    • Requests are granted in the launch order, as far as tubes and class allow; refusals are listed.
    • Each application.fighters entry carries activeAbilities.

Lesson for future models

LESSON #61: a golden fit that tests an input must set it to something the default wouldn't give. The first Fighter bay fit asked for exactly the squadrons the default launch puts out, so a break that ignored the request passed every pin.

  • For every input a fit pins, check that the default would differ.
  • Then break the code that reads it and see a pin fail.
  • Check that every harness passes the new input. dump_results.mjs didn't pass fighterStates, so check_application.py first compared both sides at the defaults and caught nothing.
