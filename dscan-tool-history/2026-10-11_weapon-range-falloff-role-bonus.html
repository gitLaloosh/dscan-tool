The fix

Added 'range'/'falloff' as new bKind values alongside the existing 'damage'/'rof' ones already used by SHIP_ROLE_BONUS -- no new table or lookup structure needed, the existing per-hull entry shape already fit. In the per-category categoryMods loop, these fold in unconditionally (same as 'rof', since range/falloff don't depend on the loaded ammo's damage type the way 'damage' bonuses sometimes do) into new rangeMult/falloffMult fields, compounding multiplicatively across multiple same-category entries (Kikimora's two independent sources). rangeByAmmo's turret branch (where TURRET_OPTIMAL_RANGE_ATTR/TURRET_FALLOFF_ATTR are read) now multiplies by catMod.rangeMult/catMod.falloffMult alongside the ammo's own range/falloff multiplier and the Sharpshooter/Trajectory Analysis skill multipliers -- an independent, non-stacking-penalized multiplicative layer, same convention as every other hull bonus in this file. A no-op (x1) for every hull without a 'range'/'falloff' entry.
