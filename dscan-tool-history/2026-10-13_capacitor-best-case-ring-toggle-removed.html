Capacitor: best case of the running modules, ring toggle removed

FeatureTest suite 2026-10-13 · v2026.10.13.26 → v2026.10.13.27

Erik: "if multiple modules can be activated separately, their impact on the capacitor should be reflected based on which ones are active. let the logic related to 'at their best' be reflected in the fit which then impacts the resulting cap state that is then presented in the capacitor and/or weaknesses cards. we can still have icons appear next to the ring that reflect any 'boosts' being applied to the capacitor." Then: "make the ASB icon clickable. if it causes problems we can change it later."

What changed

  • No boosted/unboosted toggle. The Capacitor card shows one figure: the best case of the modules that are running.
    • Every active Capacitor Booster injects. It uses the loaded charge; if none is loaded, one from cargo or the fleet hangar; if none is found anywhere, the largest compatible charge. The injection is averaged over reloads, as before.
    • Every active Ancillary Shield Booster has charges, so it uses no capacitor. This is pyfa's per-module "use" column.
    • To see a fit without a booster, set the booster online or offline in the module list.
  • Boost icons next to the ring. Each boost counted shows its module's in-game icon, and hovering gives the charge and how much it adds or saves.
    • A cyan border means the charge was loaded or found in cargo (the hover says which).
    • A dashed amber border means no charge was found and one is assumed.
  • The ASB icon is clickable for "out of charges": the ASB then runs on capacitor while the Capacitor Boosters keep injecting. A greyed, dashed icon shows that state. It is kept per fit, including on each Pilot Analyzer loss tab.
  • Card text. The ring caption lists what's counted. "Net cap rate" now reads peak recharge − active drain + Capacitor Booster injection.
  • Weaknesses card. It already used the best case, so it now matches the Capacitor card exactly.
  • Engine.
    • The primary capacitor fields are the best case. New fields: injectionPerSec, boosts (for the icons), asbDry and withoutBoosts (reference).
    • combinedConfident, combinedAssumed and boostAvailable were removed.
    • When a fit has two Capacitor Boosters and only one charge was found, the best case now includes the second booster's best charge too; before, it was left out.

Effect on existing fits (diff of every golden fit, v.26 → v.27)

Only fits with an active Capacitor Booster or ASB changed, all to their previous "boosted" figures:

  • Osprey Navy Issue (ASB): 270.9 → 33.3 GJ/s.
  • Megathron, Dominix Navy Issue, Abaddon, Leshak, Ishkur and the Vexor constructed fit: now stable.
  • Vedmak, Rokh, Sacrilege and both Curse fits: drain longer or higher stable %.
  • Rorqual (pyfa active-state fit): drain 2367.3 → 567.3 GJ/s, which is pyfa's "Use 567.33" exactly; net rate −15.7 (the pyfa capDelta pin, implant-free).

Re-pinned with notes:

  • Rorqual ×2: drain on the new basis; the old baselines moved to capacitorNoBoost*.
  • Curse ×2: time to empty 32.3 → the boosted 86.3 s pinned earlier.
  • Ishkur: stable, using its largest compatible charge.

Test-suite change: a pinned field that's missing now fails

The checker used to skip any pinned field the result didn't have. Removing combinedConfident would have turned the Rorqual's pyfa pin into a no-op while the suite still printed ALL PASS.

  • It now fails with "(not in result)".
  • The only fields this caught were three object-valued adj*ResPct_approx notes on legion_popejoy, which never worked as checks. Keys ending in _approx are now treated as informational.
  • See LESSONS_LEARNED.md #21.

Lesson for future models

When a result field is renamed or removed, its pins don't fail; they just stop checking anything. That's true unless the checker fails on missing fields, as it now does. Grep golden_fits.json for the flattened name and move every pin (LESSONS #21).
