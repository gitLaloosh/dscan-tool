Dreadnought Siege Module now modeled correctly

2026-10-12 · index.html · from the full module-dogma-attribute audit (2026-10-12_full-module-dogma-audit-findings.html), KNOWN OPEN ITEM #1 · the owner: "ok you can start with the dreadnought siege module"

Finding

All four capital "siege-class" modules — Bastion Module (Marauders), the real Dreadnought Siege Module, Triage Module (Carriers), and Industrial Core (Rorquals) — share the identical ESI/SDE group_id 515 group name "Siege Module." The tool's existing code (SIEGE_ROF_BONUS_ATTR_A/B, attrs 3108/3109) only recognized the Bastion Module's own turret/launcher rate-of-fire-doubling attributes and applied that same doubling to any module in the group — including the real Siege Module II. The user-facing methodology text went further, stating all four module types "doubled turret/launcher rate of fire while active."

Verified directly against the local pyfa SDE cache (first-party CCP data) and dogmaunits id 105 = "Percentage": the real Dreadnought Siege Module (type 4292/20280/88266) carries none of the Bastion attributes. Instead it carries:

AttributeMeaningApplies toExample value (Siege Module II)

So turrets get a large damage bonus and no RoF change under a real Dreadnought Siege Module — the opposite shape from Bastion, which doubles RoF and leaves damage alone. Triage Module and Industrial Core carry none of these weapon-affecting attributes at all (Triage instead boosts remote-repair amount; Industrial Core has no weapon effect), so the tool's prior zero-effect-for-those-two behavior was coincidentally correct, but for the wrong reason (same group name, not "no real effect").

Fix

Added four new dogma-attribute constants (SIEGE_TURRET_DAMAGE_BONUS_ATTR=2307, SIEGE_MISSILE_DAMAGE_BONUS_ATTR=2306, SIEGE_LAUNCHER_ROF_BONUS_ATTR=2305, SIEGE_HAW_ROF_BONUS_ATTR=2821) and detection in the existing per-module loop, reading whichever of these attributes a given fitted item's own dogma data actually carries — the same "read the item's own real attributes, not its group name" principle the Capacitor Recharger-group fix (2026-10-12, earlier same day) established. This means Bastion Module, real Siege Module, Triage Module, and Industrial Core are now distinguished purely by which attributes each one's own dogma carries, with no special-casing by type id or name string:

  • Bastion Module: unchanged, still detected via 3108/3109 (RoF doubling only, no damage change)
  • Siege Module (real): turret damage bonus folded into hullBonusList as ['energy'|'hybrid'|'projectile','damage',pct]; missile damage and RoF folded in separately as ['missile','damage',pct] and ['missile','rof',pct]
  • Triage Module / Industrial Core: no matching attributes present → no weapon effect, as before, now for the correct reason

Also corrected the user-facing methodology note that previously claimed uniform RoF-doubling across all four module types, and corrected the stale code comment above the Bastion-only attribute pair to cross-reference this fix.
