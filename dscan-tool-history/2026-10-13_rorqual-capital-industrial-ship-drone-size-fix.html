Rorqual (Capital Industrial Ship) light-drone misclassification fix

2026-10-13 · index.html

The bug report

the owner, pasting a fully-fit Rorqual ([Rorqual, QuadFeed], capital shield tank, mixed combat/mining drone bay including Acolyte/Warrior/Valkyrie/Berserker/Praetor/Bouncer/Curator/Warden plus Mining Drones and Maintenance Bots): "the tool is recommending warrior light drones to attack it. this is a capital ship (XL in size) huge sig radius and the tool is recommending light drones. how are we coming to this conclusion when i've seen plenty of other fits that recommend larger drones to attack them?"

Root cause

Drone size recommendation runs through two steps: sizeClassFromGroup(shipGroup.name) picks a size tier (light/medium/bc/bs/capital/industrial) from the ship's ESI group name via a lookup table (GROUP_TIER), then that tier's droneSizes array feeds droneRecommendation(), which only picks the drone RACE (from the target's weakest damage type) -- it has no sig-radius or EHP awareness of its own, it just trusts whatever size tier it's handed.

The Rorqual's real ESI group name is "Capital Industrial Ship" -- verified live against everef.net (a public EVE static-data mirror; direct ESI access was blocked from this session by network policy, so everef.net's own SDE-derived data was used instead, same grounded-verification standard, different primary source). GROUP_TIER previously mapped that exact string to the 'industrial' tier (droneSizes:['light']) -- the same bucket as Freighters, Mining Barges, Exhumers, and Transport Ships -- apparently because its group name contains the word "industrial," not because of its actual size. Its real signature radius is 11,500m (also verified live against everef.net) -- comparable to or larger than most Carriers/Dreadnoughts, nowhere near an Exhumer or Freighter's profile. The 'capital' tier (Carrier/Dreadnought/Titan/Supercarrier/Force Auxiliary, droneSizes:['sentry','heavy']) is where a hull with that signature radius belongs, and is also where every other genuinely capital-sized hull in this table already sits.

DreadnoughtCapital hull → sentry/heavyCapital hull → sentry/heavy (unchanged)—
Freighter / ExhumerIndustrial hull → lightIndustrial hull → light (unchanged)—

Fix

Moved the 'capital industrial ship' key in GROUP_TIER out of the 'industrial' group and into the 'capital' group, alongside Carrier/Dreadnought/Titan/Supercarrier/Force Auxiliary. This is the same lookup that also drives the on-page size-class label shown next to the ship's group name in the Pilot Analyzer results (.cmeta), so a scanned Rorqual now reads "Capital hull (fighters also apply, not covered here)" instead of "Industrial hull" there too -- not just the drone pick.

Flagged: this is a genuinely new area for the regression suite -- there is currently no golden-fit coverage at all for droneRecommendation()/sizeClassFromGroup() (confirmed via grep: zero existing assertions on drone-size-tier or drone-recommendation output anywhere in run_regression.mjs/golden_fits.json). A proper golden fit needs the Rorqual's full dogma_attributes payload, which this session couldn't pull from live ESI (network policy blocked esi.evetech.net directly; everef.net was used instead for the two specific facts needed here -- group name and signature radius -- but isn't a practical source for a full golden-fit fixture). Verified instead via direct function-level calls (sizeClassFromGroup('Capital Industrial Ship') / droneRecommendation()) confirming the corrected output, plus confirming Dreadnought/Freighter/Exhumer are unaffected. Worth adding real golden-fit coverage for this function family next time live ESI is reachable.
