Capacitor Battery / Power Relay / Flux Coil / Recharger now modeled

2026-10-12 · index.html · Erik: "are you accounting for cap batteries?", then provided a real pyfa screenshot of a fit for comparison

Finding

Answer was no. baseCapacitorCapacity/capacitorRechargeTimeSec read only the ship's own base dogma attributes × max-skill multipliers, plus one narrow flat-add scoped to a fitted Strategic Cruiser subsystem's own self-add bonus (the 2026-10-11 T3 fix). Zero code anywhere read a fitted Capacitor Battery, Capacitor Power Relay, Capacitor Flux Coil, or Cap Recharger's own effect -- confirmed by grep (zero hits outside one explanatory comment) and by reading the formula directly.

Fix

Confirmed live via everef.net dogma-attribute data for all four module groups, then added detection to the existing per-module loop in estimateHpAndDps() (the same loop that already handles shield/armor HP flat-adds, resist mods, etc.):

Module (real ESI group name)SlotAttributeEffect
Capacitor BatteryLow67 (capacitorBonus)flat GJ add to capacity -- no stacking penalty (flat adds never stack-penalize)
Capacitor Power RelayLow144 (capacitorRechargeRateMultiplier)% cut to recharge time only
Capacitor Flux CoilLow144 + 147 (capacitorCapacityMultiplier)% cut to recharge time AND capacity (the tradeoff)
Capacitor RechargerMid144% cut to recharge time only

Power Relay/Flux Coil/Recharger all carry the same attribute 144 (capacitorRechargeRateMultiplier), so they pool into one stacking-penalized reduction set via the file's existing applyStacking() helper -- the same "shared attribute, different module types, one stacking pool" pattern RESISTANCE_BONUS_ATTR already uses for shield/armor hardeners.

Caught mid-implementation by the regression suite: attribute ids 144 and 147 are NOT exclusive to these three module groups -- EVE reuses generic "Modifier Percent" attribute slots across unrelated effects, and a fitted Microwarpdrive on the existing loki_zkb138935092 golden fit also carries a value on attribute 147 for something else entirely. Reading it unconditionally dropped that fit's capacitorCapacity from 1875 to 1406 -- a real false positive. Fixed by gating all three reads to the module's own real ESI group name (Capacitor Battery / Capacitor Power Relay / Capacitor Flux Coil / Capacitor Recharger), not the attribute id alone.

Two candidate causes, not yet disentangled: (1) this golden fit's Flux Coil dogma stubs were cached for an unrelated 2026-10-12 Nosferatu fixture and never specifically verified for capacitor purposes -- their attr144/147 values could themselves be imprecise; (2) the Erik-chosen EVE-client closed-form stability model (average drain) is a known, already-disclosed approximation that diverges most on a fit dominated by one large, infrequently-cycling drain source (here, an X-Large Shield Booster) rather than many small staggered ones -- exactly this fit's shape. Flagged to Erik, not yet resolved -- next step would be re-pasting this exact fit into the live tool (full live ESI data, not this cached stub) to see if the gap narrows before chasing the stability-model theory further.
