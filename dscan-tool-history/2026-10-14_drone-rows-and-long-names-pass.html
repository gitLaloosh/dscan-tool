Drone rows lined up, and a long-names layout pass

LayoutBug fix 2026-10-14 · v2026.10.14.16 → v2026.10.14.17 · Erik's screenshot of a drone bay in the new Fit column (squares beside the numbers on some rows, on their own line under the name on others), then: "might want to do a quick pass to test how large strings will affect layout".

What was wrong

  • Drone rows were one wrapping flex line (icon, name, numbers, squares). In the narrower Fit column, whether the squares fitted beside the numbers depended on each row's text length, so rows wrapped differently. Reproduced with Erik's drones ('Augmented' Hammerhead, 'Excavator' Ice Harvesting Drone, Berserkers, Valkyries, Vespa).
  • The long-names pass (below) found, at phone width:
    • An unrecognized pasted line with no spaces ran out of the "Not recognized" note, and a fit name with no spaces ran out of the status line. On a phone that made the browser zoom the whole page out to ~980–1040 px, which shrank everything again.
    • The Firepower card's ammo / drone rows kept a fixed 130 px range column, squeezing long names such as Imperial Navy Multifrequency M to a few letters per line.
    • Drone squares wrapped onto a second line, because their box was sized for the 14 px desktop squares, not the 22 px phone ones.

What changed

  • Drone rows: every row is the same two-line grid: icon | name | squares on the first line (squares right-aligned in one fixed-width column, so all rows line up), the numbers under the name. Square column width is --pips squares × 18 px (26 px on a phone).
  • Long words: body{overflow-wrap:break-word}, so a word longer than its box breaks at the box's edge. break-word rather than anywhere leaves min-content sizing alone, so grid and flex columns don't squeeze names. The status line, which sits in a flex row, gets min-width:0; overflow-wrap:anywhere.
  • Firepower rows in a narrow card (a container query on .firepower-strip, under 380 px): the range moves under the name instead of a fixed column beside it.

Verification

  • Full output diff v.16 → v.17: 0 of 214 fits differ. Suite ALL PASS, parse tests 293/293, update-check chain all OK.
  • tools/page_checks/layout_check.py gains a long-strings pass at 1440 / 1100 / 375 px:
    • The test fit: a Stratios Emergency Responder carrying the longest real SDE name in each category, e.g. "Unit P-343554's Modified Omnidirectional Tracking Enhancer", "Legion Scourge Auto-Targeting Heavy Missile", "Mutated 'Excavator' Ice Harvesting Drone", "Inherent Implants 'Squire' Capacitor Systems Operation EO-606".
    • Other long strings: a 120-character unrecognized line, and a long fit name both with and without spaces, each tested in ring and list view.
    • Other tabs: the Pilot Analyzer with a 37-character pilot name (EVE's maximum), and D-scan contacts with long names.
    • What it checks: every element and every text run stays inside its column or card, with no sideways scrolling; drone squares sit right-aligned on the name line in every row.
    • Results: v.16 fails it 7 times (drone rows at all three widths; the phone page zoomed out to 976 / 1039 px); v.17 passes with FAILURES: 0.
  • Phone screenshots of the long-names fit looked at by eye for squeezing that no bounds check can see (that is how the Firepower range column was found).

Lesson for future models

  • LESSONS_LEARNED #33 (extended): test layout with the longest real strings. A single long word overflows without growing its element's box, so also check text runs. A flex or grid item needs min-width:0 plus overflow-wrap:anywhere before it can wrap. A fixed-width neighbour can squeeze text without overflowing anything, so look at the screenshot.
  • When a check finds a page that "can't be clicked" at phone width, look for an overflow first: the page may have been zoomed out.
