What changed

  • The layer icons in the Resistance rows and the Repairs rows are now in-game item icons. Each layer is shown by its buffer module, the item that adds HP to that layer:
    LayerItemType ID
    ShieldLarge Shield Extender II3841
    Armor1600mm Steel Plates II20353

    Buffer modules were picked over repairers on purpose. The Repairs header already uses the repairer icons (v.24), so using different items keeps the header columns (kinds of repair) distinct from the rows (layers).
  • The coloured layer names (cyan Shield, amber Armor, brown Hull) are unchanged and now carry the layer identity alone.
  • The icon column in all four grids (Resistance column labels and rows, Repairs header and rows) went from 18 to 20 px, the same size as the module icons in the Fit card.
  • New layerIconHtml(layer, extraClass, title) wraps the shared eveTypeIconHtml(). Hover text sits on the HTML wrapper. If CCP's image server can't be reached, the old SVG glyph is shown in the layer colour instead.

Drone bay: squares only up to what can be in space

Erik, mid-change, with a screenshot of a 30-Acolyte bay drawn as 30 squares: "there is no need to have visual representation of slots beyond their limit of active drones of that type... show the number of items in the bay but only a visual representation of slots for the maximum allowable to activate at once."

  • Squares per drone type: the most this fit could ever have of that type in space. That is the smallest of:
    • the number in the bay
    • the in-space limit (5)
    • the ship's drone bandwidth ÷ that drone's bandwidth
    Examples:
    • Dominix (125 Mbit/s): 30 Acolytes give 5 squares, 5 Excavators give 5.
    • Tristan (25 Mbit/s): 2 Ogres give 1 square.
    A type that can never launch on this hull still shows one locked square, whose hover text gives the reason.
  • Bay count: now text, "n in space · m in bay". It was "n / m in space", which read as if all m could launch.
  • Dashed squares now mean only "room currently taken by other drones". Example: with 2 Praetors out on the Dominix, every other type shows 3 open and 2 dashed.
  • Code: new droneTypeFitCap(), used by droneBayStatesHtml(). The square-column width now follows the largest cap (at most 5 here), not the largest bay stack.
  • Engine: no change. Launch requests, ordering and refusals are as in v.23.

Bug fixed along the way

Every stroked SVG glyph in the Resistance and Repairs cards, and the capacitor-booster bolt, drew a faint coloured square around itself. The cause was the transparent hover rectangle added by an earlier hover fix (<rect fill="transparent">). It inherited the parent SVG's stroke="currentColor", so it drew a 24×24 outline. That fix's comment had claimed "zero visual change". Adding stroke="none" to the rectangle keeps the hover area and removes the box. On Erik's machine this now only matters for the fallback glyphs, because the in-game icons load there.

Lesson for future models

SVG children inherit fill and stroke from the root <svg>. An invisible helper shape, such as a hover hit area, needs both set explicitly (fill="transparent" stroke="none"). A screenshot at 15 px can hide a 1 px outline. Compare zoomed screenshots, or take before/after crops, before writing "zero visual change".
