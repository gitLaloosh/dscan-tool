The browser extension: right-click zKillboard to open it in ETA

FeatureTests 2026-10-27 · v2026.10.14.79 → v2026.10.14.80 · extension 1.0.0.

From the backlog (the owner, 2026-10-25: "create a google chrome extension that would let me right click on a pilot name or killmail in zkillboard.com and send it to the tool"), built after the shared killmail links (v.79). The owner: "ok build the browser extension please", the tool's address https://gitlaloosh.github.io/dscan-tool/, and the menu items: "all three please".

What you get

  • A Chrome extension in the repo's browser-extension folder, with five right-click items:
    • on a link to a kill, or a kill's page: Open kill in EVE Threat Assessment (the shared-killmail view);
    • on a link to a pilot, or a pilot's page: Analyze pilot in EVE Threat Assessment (the Pilot Analyzer for that pilot);
    • on selected text on any page: Analyze "<text>" in EVE Threat Assessment (a selected zKillboard link opens that kill or pilot instead).
  • Install: chrome://extensions → Developer mode → Load unpacked → the browser-extension folder. It works in Edge and Brave too. Its options page changes the tool's address (default: your GitHub Pages address).
  • Permissions: right-click menus and storage (for the address) only. It reads nothing from the pages you visit and makes no requests of its own: it opens the tool with the ID or name in the address.
  • The tool reads three new links: #zkill=<killmail ID> (it gets the hash from zKillboard, as for a pasted kill link, and the address then shows the share link), #pilot=<character ID> (the name from ESI) and #pilotname=<name>. Each runs what typing it would. A pilot link stays in the address until another analysis starts, so a reload runs it again.
  • New error code SHARE-03: a pilot link with an ID ESI doesn't know as a pilot, or no name.

Checks

  • New tools/page_checks/extension_check.py: Chromium loads the extension. It checks the manifest's permissions; that the five items exist; the link each click makes (10 cases); end to end, that a kill link, a pilot link and a selected name open the right view, and an unknown pilot shows SHARE-03; and the options page. v.79 fails 4 (the tool doesn't read the new links); mutations: #pilot= not read fails 2; a pilot link that clears the address fails 1; #zkill= not read fails 1.
  • New tools/page_checks/killmail_mocks.py: the zKillboard and ESI answers shared by shared_kill_check.py and the new check. ESI's /universe/names now gives each ID its category and answers 404 to an unknown ID, as it does.
  • Regression ALL PASS (269 fits), update chain all 42 steps OK, all 31 page checks 0 failures, the three lints 0 problems; ERRORS.md regenerated (32 codes). PYFA CORE untouched. A first mutant run, with the chain and every page check running at the same time, showed SHARE-03 for a real pilot: a failed ESI lookup was being reported as "not a pilot". Only ESI's 404 means that now; any other failure shows its own error code. The real check then passed three runs in a row.

Lesson for future models

LESSON #72: a tab a browser extension opens isn't routed on its first load.

  • The extension's new tab showed Chrome's error page: it starts loading before Playwright attaches, so a made-up host routed by Playwright never answered.
  • Serve that page from a real local web server and route only the page's own requests. Extensions also need Chromium's new headless mode.
