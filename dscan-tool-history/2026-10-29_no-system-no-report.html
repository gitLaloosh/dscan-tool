No system, no report

FixTests 2026-10-29 · v2026.10.14.101 → v2026.10.14.102

The owner's bug report, through the inbox: "intel feed parsing error", with a screenshot of the Feed. Two rows had no system: one said "CLEAR", the other had only "STATUS?". Another report showed a pilot with a "Probe" ship. When asked to fix it, he added: "perhaps we shouldn't generate a 'report' if it doesn't contain a valid system name."

What the lines were

I read his intel log around the screenshot's minute, for the lines' shape only (nothing from it is saved here):

  • 78 status?: a system shortened to two characters. That's too short to place, so the page made a "STATUS?" row with no system.
  • clr, on its own: the answer to that question. The page made a "CLEAR" row with no system.
  • <system> <pilot> probe, then <system> clr three seconds later: a pilot passing through in a Probe frigate. The page read it correctly, so nothing changes there.

What you get

  • A line with no system the page can read makes no report. It gets no Feed row and changes nothing in Near You. Its words aren't looked up as pilots either, which saves an ESI request for chatter.
  • Such a line still counts as the channel's "last line" in the status line, so a busy channel still looks busy.
  • Lines with a system are unchanged, including "<system> status?".
  • Not done: linking an answer ("clr") to the question it answers. A two-character system can't be placed, and a guess could clear the wrong system.
  • No number the engine works out changed. ERRORS.md is unchanged (46 codes).

Lesson for future models

LESSON #92: a screenshot shows the page's output, not its input. From the picture, "Probe" looked like the scanning-probes word read as a ship, and a fix was being planned for it. The line itself showed a pilot in a Probe, read correctly. Find the input (the log line, the paste, the killmail) and decide from it what the page should have shown before changing the parser. Read real logs for their shape only and never save them.
