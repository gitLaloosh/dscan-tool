1. Cap-drain gauge (backlog item, logged earlier the same day)

Erik: "would rather have a graphic of some sort with the duration in the middle so it's easy to see and read -- right now it's just too wordy." The old capacitor.weak row was a red "!" badge plus a full run-on sentence (margin GJ/s, neut/nos pressure clause, all in one line). Replaced with a small radial gauge (capWeakGaugeHtml()):

  • Ring fill = the capacitor's remaining stable headroom -- stablePct when it settles somewhere (always under CAP_STABLE_WEAKNESS_PCT_THRESHOLD=25 here, since this row only renders when already flagged weak), or 0 when it's genuinely unstable and draining to empty (a "near-empty tank" reading, not a 0%-looks-like-nothing's-wrong reading -- the track itself is tinted red, not neutral gray, so an empty ring still reads as "in danger").
  • Centered figure = exactly Erik's ask: the duration (time-to-empty, e.g. "21s"/"2m 1s"/"4h+") for the unstable case, or a rounded whole-percent (e.g. "18%") for the stable-but-thin case -- same split capCardStateText() already uses on the Capacitor card, just condensed to fit a 50px ring (whole-percent instead of 1-decimal; the exact figure is still in the hover tooltip).
  • Caption: a short 2-line label next to the ring instead of the old sentence -- a bold headline ("Capacitor drains dry" / "Thin cap margin") plus one short actionable line. The stable-but-thin case keeps its single most useful number inline (the GJ/s margin), since that's the one figure a player can actually act on.
  • Full original sentence (margin GJ/s, neut/nos pressure clause) isn't deleted -- it's a hover title= tooltip on the gauge, same convention the TD Mode buttons already use. Nothing lost, just decluttered.
  • The old standalone "!" badge is dropped -- the ring's red color already carries that signal, and keeping both would be the exact kind of duplicate-signal Erik called out and removed earlier the same day (EWAR card's "Cap-lean target" badge, which restated the same capWeak signal a second time).

Track color: --danger at 18% opacity (not the neutral --line the Resistance card's bars use), specifically so a 0%-fill ring still reads as "in danger" rather than "empty/unset control." Pure rendering change -- zero new calc, reuses stable/stablePct/timeToEmptySec/timeToEmptyCapped/netRate/weakReason, all already computed and regression-tested by the capacitor-stability-model work earlier this week.

2. "Total DPS if cargo ammo" list moved from Weaknesses to Firepower

Pure placement change, no data/calc impact -- hasCargoGuess was already computed in that function for the Total/Weapon DPS tiles' own range display, just reused rather than duplicated.
