1. Pasted names with either apostrophe

  • CCP's names use both kinds of apostrophe. The October data build 3624425 renamed Sarikusa’s / Horm’s / Zorya’s officer modules to a straight '. ‘Vigilant’ Shield Command Burst, Tenzin’s Modified Guidance Disruptor and 26 other published names still use curly quotes. A blind conversion either way would break one of the two sets.
  • resolveNamesToIdsFlexible already sent a title-cased variant with each name. It now also sends apostropheVariants(name): every quote straightened, and every straight quote curled (‘ at the start of a word, ’ elsewhere). ESI resolves whichever spelling exists, and the item is shown under CCP's name. The D-Scan box and the Pilot Analyzer use the same function.
  • New check tools/independent_checks/check_apostrophe_names.py (in the chain): all 3,204 published names with an apostrophe, each typed 3 ways, 0 misses. It fails on v.28.
  • Page check: an EFT with Sarikusa’s Capital Energy Nosferatu (old curly spelling) and one with 'Vigilant' Shield Command Burst (straight) both resolve and show on the EWAR card. On v.28 neither appeared.
  • Manifest: erikPyfa = v2.69.3 / data 3624425 (Erik updated on 2026-10-22). Screenshot comparisons match the verified version again.

How (PYFA CORE ewar-calc, re-verified and re-locked)

  • gen_ewar_table.py:
    • EWAR_GROUPS += Burst Jammer, Burst Projectors.
    • New attributes: ecmBurstRange, doomsdayAOERange / Duration, doomsdayWarningDuration and the four durationXBurstProjector attributes.
    • Result: 8 new effects and 6 new skill rows. No existing row changed.
  • Two generator fixes on the way:
    • Effect2982 tests whether the module has the duration attribute. A test like that is now accepted when the tested attribute is the one being boosted or multiplied and its SDE default is 0, since a module without it stays at 0 either way. Anything else still fails.
    • Filters ran on one module per (skills, group) signature. The seven Burst Projectors share one signature but carry different duration attributes, so four of Effect2982's five rows matched nothing and were skipped. Filters now also run on every EWAR module. See LESSONS #28.
  • Engine: kinds burstJammer and projector. The projector type comes from its doomsday effect id (BURST_PROJECTOR_EFFECT_KIND). The legacy hand path skips both kinds.
  • compare_ewar.py now also compares burstRadiusM, fieldRadiusM, fieldDurationSec, warningSec, affectedSec and the neut amount.

Lesson for future models

  • A "not done" backlog line can be as stale as a "nothing found" note (LESSONS #5). Build the test fit and compare with pyfa before writing code: the ZPME took one fit to close.
  • One representative per signature is only safe while the filter tests skills and group. When a filter asks whether an item has an attribute, run it on every item it could reach (LESSONS #28).
