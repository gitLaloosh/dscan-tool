Problem

Speed, align time and mass used hand-built inputs: lists keyed by module group (VELOCITY_*, AGILITY_*, MASS_BONUS_PERCENTAGE_GROUPS), a 4-entry subsystem table and fixed skill constants. What changed

  • New PYFA CORE section speed-calc:
    • SPEED_EFFECTS (82 effects) and SPEED_SKILL_ROWS (one row per skill, value at V), generated by the new tools/gen_speed_table.py in two passes. It records every handler on ship maxVelocity / agility / mass, then every handler on the module attributes those rows read: rig drawbacks (halved by the rigging skills), plate massAddition, cloak maxVelocityModifier, and prop speedFactor / speedBoostFactor. Conditions it records:
      • the hull's required skills (Effect1616 Capital Ships)
      • "while cloaked" (fit.extraAttributes['cloaked'], set by SPEED_CLOAK_EFFECTS)
    • pyfaPropBoost is pyfa's Effect6730 / 6731 (MWD / AB), line for line: mass += massAddition, then maxVelocity is boosted by speedFactor × thrust / mass in the postMul group. The generator fails if pyfa changes those handlers.
    • pyfaShipSpeed runs the whole calculation (skills, hull, modules by state, mode); align = −ln(0.25) × agility × mass / 106 (Fit.alignTime).
  • The shared attribute pool (resist-calc) now carries pyfa's pre- and post-increases, which plates and prop modules need. Resists re-verified: 0 of 194 differ.
  • The hand tables and skill constants remain only as the fallback for a hull record without effects.
  • Input choice: Cynosural Field Generators now default online, like MJDs and cloaks. A fitted cyno isn't necessarily lit, and an active one shows 0 m/s. Setting it active gives pyfa's result. Recorded in DEVIATIONS.md.
  • Tooling:
    • compare_speed.py and gen_speed_table.py joined the chain (16 checks)
    • pyfa_effects.run(..., rich=True) records getSkill, ship.item.requiresSkill and extraAttributes (LESSON #28)

Not changed

  • Stasis webifier and other non-propulsion speedFactor bonuses: EWAR, phase 4.
  • Overheated prop modules: not modelled.
  • Implants and boosters: backlog.
  • Entosis speedLimit: pyfa writes it to fit.extraAttributes, but Fit.maxSpeed reads the ship attribute, so pyfa never caps speed. The tool matches that.

Lesson for future models

  • A recorder error is a handler you didn't record. Read every error a recorder run reports. Cloaks, Triage and the capital agility skills were all hidden in a list of "unrelated handler errors" (LESSON #28).
  • Follow a value back through everything that modifies it. The rig drawback a speed row reads is itself halved by a skill (LESSON #20), so the generator's second pass records modifiers on every module attribute the ship rows read.
  • When filters are tested on one representative per signature, compare signatures, not type ids.
