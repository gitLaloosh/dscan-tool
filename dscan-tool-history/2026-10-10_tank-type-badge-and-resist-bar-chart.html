Tank Type badge + resistance bar chart

Date: 2026-10-10   Status: Delivered, verified via 28/28 regression PASS (exact expected values, not just ranges) + direct unit test of the new render functions + real-Chromium screenshot of the new markup against the tool's real CSS

Origin: two separate threads converged into one implementation. First, Erik asked "I like option A but the resistance data isn't very easy to discern at a glance... make it look more like a chart with the biggest resistance hole at the top," then "can you please make it very apparent as to whether a fit is shield, armor or hull tanked?" and asked both be combined into one new mockup iteration. After reviewing the mockup, Erik separately noticed the live tool's existing resist display showed no visible color and asked whether that was intentional. Investigation found it was a side effect of an earlier request (show resists "less prominent than effective HP"), implemented by stacking .dmg-badge's .sm (small) and .faded (opacity:0.4) modifiers — which, combined with Kinetic's already-low chroma (flagged during the mockup's accessibility pass), washed the color out further than intended. Erik then said "let's implement it," referring to building the approved Option A iteration 2 direction (both the resist chart and the Tank Type badge) into the live tool.

The changes

Tank Type badge: a new "Tank type" subsection above "Weakest damage type" showing SHIELD TANK / ARMOR TANK / STRUCTURE TANK / MIXED TANK, classified by each layer's share of this fit's RAW (pre-resist) HP — not effective HP, since raw share answers "where does most of this fit's health actually sit" without double-counting the resist profile the chart below already shows separately. A layer needs ≥60% of raw HP to be named outright; below that it's shown as "Mixed." Computed entirely from HP values the tool already calculates (shieldHP/armorHP/hullHP inside estimateHpAndDps(), before they're divided by resonance to become effective HP) — no new ESI calls. Shield and Armor use a validated 2-color categorical pair (--tank-shield:#1f9ab3, --tank-armor:#b9812f), confirmed via the dataviz skill's validate_palette.js to clear all six categorical-palette checks together in dark mode (lightness band, chroma floor, CVD separation ΔE 17.2 protan / 22.0 tritan, normal-vision floor ΔE 21.3, contrast). The rare Structure-tank case and a genuinely Mixed fit both use a neutral dashed-outline badge instead of a third saturated hue — several 3-color candidate sets were tried and repeatedly failed the chroma-floor or contrast checks alongside the validated pair, so a non-filled treatment was used instead (it doesn't need to compete in the same categorical-chroma space as a filled swatch).

Resistance bar chart: replaces the original flat badge-row implementation (resistSummaryHtml) with resistChartHtml — one small chart per layer that actually has HP behind it (Shield/Armor/Structure), each showing all 4 damage types sorted ascending by resist% so the biggest hole sits on top, visually emphasized (taller bar, full opacity, bolder label) versus the other three (shorter, opacity 0.6). Root-cause fix for the "no color" report: the old version stacked .dmg-badge's .sm + .faded (opacity:0.4) on top of hues already close to the chroma floor, reading as nearly colorless. Bars now use the same per-type color variables as every other damage badge in the tool, at full saturation — "less prominent than effective HP" comes from being a small chart tucked under the EHP tile, not from fading the hue away.

What's next

Three follow-on ideas came up alongside this change, not yet started: (1) effective range/falloff/max travel distance for the weapons and ammo already feeding the DPS estimate — straightforward for turrets (same loaded-ammo/cargo-fallback pattern as DPS), genuinely harder for missiles (range isn't a single number; it depends on target signature/velocity vs. the missile's own explosion radius/velocity, a mechanic this tool doesn't model anywhere yet); (2) an active-rep vs. buffer-fit indicator — easy, since it only needs a new module-group check (Shield Booster/Armor Repairer/Hull Repairer) in the same per-item classification pass already used for resist mods and the Propulsion badge, zero new ESI calls; (3) the DPS required to break an active-rep fit's sustained tank — a natural follow-up to (2), needs the repair module's own dogma attributes verified live against ESI before building (same primary-source standard as everything else here).
