Layout Phase 1: three columns on desktop, one on phones

LayoutMobileBug fix 2026-10-14 · v2026.10.14.14 → v2026.10.14.15 · Backlog "Mobile-friendly layout" (via todo-inbox: "it is difficult to see and read on mobile"), "Fit view you can see and change without scrolling", bug list #1 "Changing a module's state makes the page jump". The owner: "i really think something similar to eveworkbench's layout would be a good point of reference", then "both with a switch like workbench" for the fit view.

What was checked first

  • EVE Workbench's fit page (built-in browser): desktop = info column | the fit (a ring of modules around the ship render) | a narrow column of compact stat panels (Firepower, Resource usage, Resistance, Capacitor, Repairs, Targeting & misc). On first visit it asks for a view: Radial "best for Desktop and Tablet users" or List "best for Smartphone users". Phones stack everything in one column.
  • Why the tool was hard to read on a phone: loading the page in Chromium at 375 px with mobile emulation showed index.html had no viewport meta tag, so a phone drew it as a ~980 px desktop page shrunk to fit (with uneven text inflation), and there were no phone styles. With the tag added, the only real overflow was a drone row's numbers (.ds-meta{flex:none}).
  • Render paths: the Fit Analyzer (renderFitAnalyzerResult) and each Pilot Analyzer loss (renderFitTabs) both build the summary cards with renderFitSummaryHtml(f) and the Fit card with fitCardHtml(), in two separate containers; the Fit card was last on the page, below every card a state change recalculates.
  • A mockup canvas ("D-Scan Analyzer layout": desktop ring, desktop list, phone) was reviewed first; the owner chose both fit views with a switch. Delivered in three phases: this layout (v.15), the ring view with a Ring / List switch (v.16), collapsible cards with summaries (v.17).

What changed

  • Viewport tag added. Phone styles (< 600 px): less page/panel/card padding, finger-sized state buttons (34 px) and drone squares (22 px).
  • One layout per fit: new fitLayoutHtml(f, idToName, cardOpts) returns a .fit-layout grid with three areas. fitSummaryParts(f) (was the body of renderFitSummaryHtml) returns the cards in two groups; card markup and order within each group are unchanged.
    AreaHolds
    .fl-beathow to beat it: mode selector, Weaknesses, EWAR / Misc
    .fl-fitthe Fit card (module states, drones, implants, cargo)
    .fl-statsFirepower, Resistance + Repairs, Navigation & targeting, Capacitor
  • Columns by width: phone (< 900 px) one column, beat → fit → stats; tablet (900–1279 px) the fit on the left with beat and stats stacked on the right; desktop (≥ 1280 px) beat | fit | stats, as on EVE Workbench. The page is now up to 1440 px wide (was 980); long intro text is capped at 860 px.
  • Sticky fit column from 900 px up: it stays in view while the stats scroll, and a state change no longer moves it. This closes bug list #1 (the page jumped because the Fit card sat below the cards it recalculates).
  • Re-rendering: every control (mode buttons, ASB out-of-charges toggle, module states, drone squares, reset) now rebuilds that fit's whole layout and re-wires all of them (Fit Analyzer rerenderAll()/wireAll(), Pilot Analyzer rerenderTab(i)/wireTab(i)), replacing the separate summary/card wrappers and their duplicated wiring.
  • Pilot Analyzer Fit card: still collapsible (the owner's D1: a killmail never says what was running) but starts open at 900 px and up, where it has its own column; on a phone it starts closed as before.
  • Narrow columns: a drone's name keeps 110 px (its numbers wrap below), the capacitor state tile takes a wider share. Fit card legend now says "every card recalculates" (the cards are beside it, not above).

Not in this phase

  • The ring view and the Ring / List switch (v.16); collapsible cards with one-line summaries (v.17).
  • The cards' own insides are unchanged; some stat tiles stack in the narrower side columns.

Lesson for future models

  • LESSONS_LEARNED #33 (new): check a layout at a real phone width with mobile emulation, not only a desktop screenshot; the missing viewport tag was invisible in every desktop check. Any layout change runs tools/page_checks/layout_check.py (checklist step 10 now says so).
  • When markup moves into one container, every control that re-renders part of it must re-render and re-wire the whole container; click each one at each width.
