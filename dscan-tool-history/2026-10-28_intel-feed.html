Intel: watching your intel channels (delivery 1)

The owner via todo-inbox: "the tool actively polls the game's chat log for the intel channel and tracks neutral and hostile ships that are reported via that channel"; then "it needs to have an on/off mechanism. once started it will be watching that chat log constantly so an off switch is a must as well." Mockup answers: "the tab has the feed in a card. settings button (little gear icon or something), prefer a slider for off/on similar just like 'use in assessments'"; jumps from a built-in table "as long as it is accurate and doesn't get out of sync with eve updates"; two deliveries; his logs read for the format only. Mid-build: "do not save any raw intel to the repository ... if you need to build your own test data, fine but dont use raw intel." Plan: roadmap/intel-plan.md; mockup Claude outputs/intel_mockup.html.

What you get

  • An Intel tab after the System Analyzer, with one Intel card, and an Intel slider beside Standings on every tab, in the "Use in assessments" style. The two sliders are one switch; either turns it off, and so does closing the page. While on, the top slider shows "N near": systems with a hostile or neutral report within your alert range.
  • Setup (the card the first time; the gear afterwards): EVE's Chatlogs folder (Chrome or Edge ask once; after a browser restart the slider asks once more), the intel channels found there (logs of the last 2 days), which character is you (from your Local logs, with their current systems), and alerts: range (3 jumps), sound, desktop notification, how long reports stay (15 min), hide friendlies. Kept in this browser.
  • Near You: each system reported in that time, nearest first, with jumps from you and its latest report: clear, no visual (keeping who was seen), or how many hostile or neutral and who and what. A red row is a hostile or neutral report within range.
  • Feed: every line, newest first: the system and its jumps, pilots coloured by your Standings, +N, ships with counts, the words recognized; words it couldn't place stay plain; the raw line underneath.
  • Alerts: a short sound and a desktop notification ("8WA-Z6 · 1 jump") for a hostile or neutral report within range, once per system every 30 seconds; never for friendlies, never for lines already in the log when it starts.
  • Your system follows you: the page reads your Local log's "Channel changed to Local" as you jump, and jumps are redrawn. A relog's new log file is found within 15 seconds.

How it works

  • Reading the logs. The File System Access API (no EVE login: ESI has no chat). The folder handle is kept in IndexedDB (eta-intel). A worker ticks every 2 seconds (a hidden tab slows the page's own timers to once a minute; a worker's are not), and each tick reads only the new end of each watched file: UTF-16 LE, a BOM on every line, a header with the channel and listener, then [ yyyy.mm.dd hh:mm:ss ] Speaker > message in EVE time. A long session's log is read from its last 2 MB.
  • Reading a report. Word by word: systems first (whole names in any case when they have a digit or '-', Title Case for names like Jita, up to three words like New Caldari; or the start of a null-sec name, read as the nearest such system to you), then ships (every published ship's English and Chinese name, with x2 / 2x), then +N, clr, nv, status? and filler words. What's left is looked up on ESI as pilot names, 1 to 3 words at a time (one request per tick), keeping the split that names the most words with the fewest pilots; ESI also answers near matches, so only exact names count. A '*' after a linked name ends it.
  • Jumps that stay in sync. The stargate list is the EVE client's own res:/staticdata/jumps.static: 6,989 connections between 5,268 systems, client build 3654997 (read from C:\CCP\EVE, read only; checked against ESI's stargates for 1DQ1-A and Jita). tools/gen_intel_tables.py writes it into the page (51 KB) with the build and the file's md5, and a new update-check step compares it with the client whenever the files are staged. When Intel starts, the page asks ESI which build Tranquility runs; after a patch it says so in the card until the table is re-checked. Stargates only: no jump bridges, no wormholes.
  • System names come from ESI's /universe/names/ the first time Intel starts (6 requests) and are kept in the browser; the client's file has IDs only.
  • Requests: ESI only (names, pilot IDs, affiliation for Standings, the build). Nothing from the logs is sent anywhere else or kept after the page closes.
  • New error codes INTEL-01 (a browser without the API), INTEL-02 (the folder can't be read), INTEL-03 (system names didn't load), INTEL-04 (no chat logs in the folder); ERRORS.md has 45. New card names Intel, Near You, Feed.
  • No number the engine works out changed.

Checks

  • New tools/page_checks/intel_check.py with a made-up Chatlogs folder written the way EVE writes it. Every line, pilot, character and channel in it is invented; no raw intel is in the repository. It decodes the page's table in Python and compares jumps from 1DQ1-A (17 systems, Jita 42) and, with EVE_RES, the table with the client's file. v.95 fails (no Intel tab).
  • Mutants caught: the BOM left on lines, a shortened system read as the first match instead of the nearest, alerts ignoring the range, alerts for lines already in the log, a timer instead of the worker, pilot names split into single words, the header slider not following the card's, the 15-minute window ignored at the start.
  • sa_size_check.py failed once on its own arithmetic: it rounded "N d ago" the Python way (36.5 days became 36; the page says 37). It now rounds as JavaScript does (LESSON #34 again).
  • header_check.py and system_analyzer_check.py expect the Intel tab. check_card_names.py skips long strings with no whitespace (LESSON #82).
  • Regression suite ALL PASS (269 fits); the update-check chain (43 steps); all 42 page checks; lints 0 problems.

Lesson for future models

LESSON #83: a test double must replace the real thing, not fill in when it's missing. The check left showDirectoryPicker unstubbed to test the "no API" error, but Chromium has its own, so the case never ran. Assign the stub in every case (= stub or = undefined). And LESSON #82: a lint that scans the page's strings hung for minutes on the 50 KB base64 table; data strings aren't prose, skip them.
