Scan resolution / sensor strength universal-skill fix + T3D Sharpshooter Mode sensor bonus

2026-10-12 · dscan-tool.html · bug report: "log a bug that the scan resolution and sensor strength for the following fit differs in pyfa than it does in the tool" (real Svipul EFT fit)

The report

Erik pasted a real Svipul fit and a pyfa screenshot showing Scan res. 662mm / Sensor str. 13.2 / Range (targeting) 50km. The tool's own Navigation & targeting card showed the hull's raw, unmultiplied base attributes instead.

Root cause #1 — universal skill multiplier entirely missing

scanResolution and sensorStrength were read straight off ship dogma attributes 564 (scanResolution) and 208-211 (the 4 scan-strength types), with no skill multiplier at all — unlike targeting range, which already carries MAX_LONG_RANGE_TARGETING_MULT=1.25.

Two earlier "exhaustively checked, nothing found" claims already in this file turned out to be wrong:

ClaimDateWhat it missed
Phase-2 feasibility note (scan resolution)originalSignature Analysis skill (type 3431)
Loki sensor-strength "RESOLVED, not a bug"2026-10-11Sensor Compensation skill family

Both missing skills live in ESI skill group 1213, named "Targeting" — the very group both prior checks claimed to have already covered. Confirmed live via each skill's own ESI description text (same evidentiary bar this file already uses for Long Range Targeting):

  • Signature Analysis (3431): "5% improved targeting speed per skill level" — EVE's own targeting-speed formula has no input besides signature radius and scan resolution, so this is a scan-resolution multiplier in all but name.
  • Ladar/Gravimetric/Magnetometric/Radar Sensor Compensation (33001/33000/32999/33002): "Each skill level increases [X] Sensor strength by 4%" — type-specific to each of the 4 SCAN_STRENGTH_ATTRS.

Fixed with the file's standing max-level-V convention: MAX_SIGNATURE_ANALYSIS_MULT=1.25, MAX_SENSOR_COMPENSATION_MULT=1.20.

Root cause #2 — T3D Sharpshooter Mode's sensor/targeting bonus, known but never wired up

All 4 Tactical Destroyer hulls (Confessor/Hecate/Jackdaw/Svipul) get +100% sensor strength and +100% targeting range in Sharpshooter Mode, confirmed via everef.net trait text back on 2026-10-08 when the T3D Mode mechanic was first built. Only the weapon-damage half of that bonus was ever actually applied in code (tdSharpshooterMult) — the sensor/targeting half sat in a code comment, never gated into any calculation. Since the tool defaults every T3D estimate to Sharpshooter Mode, this silently under-reported those two stats on all 4 hulls regardless of fit.

Fixed: TACTICAL_DESTROYER_SHARPSHOOTER_SENSOR_MULT=2.0, gated on the identical condition the damage bonus already uses (tdBonus && tacticalMode==='sharpshooter'). Confirmed via everef trait text that Sharpshooter Mode does not touch scan resolution — only sensor strength and targeting range — so the mode multiplier is applied to those two only.

The tool's own default (Sharpshooter) view will correctly show the higher, mode-boosted numbers; toggling to Defense/Propulsion Mode in the UI reproduces pyfa's figures.

A pre-existing golden fit (loki_zkb138935092, a real killmail) already had a pyfa-sourced sensor-strength figure on file: 20.4, vs. the tool's old raw 17. The 2026-10-11 investigation of that exact discrepancy reached the right number (17×1.20=20.4) but attributed it to the wrong mechanism — a hypothetical "Loki fitted with a different Core subsystem" theory, closed as "not a bug." That theory is now known to have been a coincidence: 1.20 is the universal Ladar Sensor Compensation multiplier, unrelated to which subsystem is fitted. This fit's pinned expectation is corrected in place (17→20.4) with the real explanation.

Scope
