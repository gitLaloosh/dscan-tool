EWAR card renamed "EWAR / Misc" + cyno-fit flag

2026-10-12 · dscan-tool.html · addresses backlog item "cyno-fit flagging"

What shipped

The EWAR card is now titled "EWAR / Misc" and also surfaces notable fitted modules that aren't EWAR themselves but materially change the threat picture. First (only) trait implemented: a fitted Cynosural Field Generator, flagged in red/danger styling with the note "can bridge in capital ships, Black Ops, or jump freighters within seconds -- treat as a reinforcement threat independent of this ship's own stats".

Grounding (live ESI, not assumed)

Confirmed the Cynosural Field Generator group (id 658) live via ESI rather than assuming which variants exist: exactly 3 published types --

  • Cynosural Field Generator I (21096) -- visible to anyone; any capital/Black-Ops jump drive can lock onto it
  • Covert Cynosural Field Generator I (28646) -- undetectable except to a Black Ops jump drive
  • Industrial Cynosural Field Generator (52694) -- Jump Freighter/Rorqual-only

All 3 confirmed High-power-slot modules (each type's own dogma_effects carries effect 12 "hiPower"). The tool flags a fit regardless of which of the 3 variants is fitted -- the threat (a capital/BLOPS bridge landing within seconds) doesn't depend on which jump-drive class can see the cyno, only on whether one is fitted at all.

Implementation

New MISC_TRAIT_GROUP_INFO constant, keyed by lowercased ESI group name (same lookup convention as the existing EWAR_GROUP_INFO), each entry carrying {note, severity}. Detection added as one extra check inside the SAME defensive-slot loop that already builds ewarModules -- no second pass over fitted items. New miscTraits accumulator/result field, parallel to ewarModules. ewarCardHtml() updated to group+render both lists together under the renamed title; the card is now omitted only when BOTH lists are empty. Misc trait chips get their own "!" badge using the existing --danger color token (already used for error states elsewhere in this file) -- not a new color.

This is a narrow, self-contained first slice of the broader "cyno-fit flagging" backlog item -- it covers detection + display of a fitted cyno only. It does not (yet) do anything with that information beyond displaying it (e.g. no separate warning banner, no cross-reference against other fit traits). Future misc-trait candidates (if any come up) slot into the same MISC_TRAIT_GROUP_INFO table without further architecture work.

Verification

run_regression.mjs gained a miscTraits flattening block (mirrors the existing ewarModules one): miscTraitCount (summed qty) and hasCynoFitted (always 0 or 1, so absence is assertable too -- same "assert absence separately" convention as hasEwar).

New golden fit rifter_constructed_cyno_fitted: bare Rifter (reused from the existing missile-application fit) + 1x Cynosural Field Generator I in a High slot, nothing else -- isolates the detection mechanism cleanly. Also asserts hasEwar: 0 on this fit to confirm the cyno module isn't double-counted as an EWAR module (no group-name collision between the two lookup tables).

Negative controls added to 2 existing fits rather than built from scratch (reusing the same fits that already serve as hasEwar negative/positive controls): abaddon_zkb138966900_cargo_fallback (no EWAR, no cyno) and curse_zkb139073592_ewar (real EWAR, no cyno) both now assert hasCynoFitted: 0.

Full suite: 74/74 fits, ALL PASS.
