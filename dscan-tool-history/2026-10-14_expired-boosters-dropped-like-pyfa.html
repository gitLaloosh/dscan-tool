Expired event boosters dropped, as pyfa does

Bug fixPYFA COREVerification 2026-10-14 · v2026.10.14.13 → v2026.10.14.14 · from the owner's pyfa screenshot of the Rupture check fit

Problem

For the Rupture check fit pyfa showed Weapon 284 DPS, volley 1,048 and 1.8 km + 14.4 km; the tool (and the reference oracle) said 301 / 1,111 / 15.2 km. pyfa's Additions tab read Boosters (2) for three booster lines. The difference is exactly Strokar Booster VI (+6% projectile damage, +6% falloff): the oracle without it gives 283.9 DPS, 1,048 volley, 14,358 m.

Root cause

pyfa's database is built from the SDE by db_update.py, which deletes every booster whose boosterLastInjectionDatetime is before the data dump ("Remove boosters which were expired at the time data dump was generated"). Strokar Booster VI could be injected until 2026-08-26; pyfa's data is from 2026-10-06. pyfa's EFT import (service/port/shared.py fetchItem) then finds no such item and skips the line without a message (the owner's pyfa log for today shows the Pyrolancea and Frentix effects loading and none of Strokar's). 130 published boosters are affected. The same step also unpublishes items named like abyssal / mutated / _PLACEHOLDER.

Fix

  • tools/pyfa_sde.py pyfa_removed_types() mirrors those removals (dump time from staticdata/phobos/metadata.0.json).
  • gen_implant_table.py leaves them out and writes PYFA_REMOVED_IMPLANT_IDS (130 ids) into PYFA CORE implant-calc (re-locked; IMPLANT_EFFECTS now 303 effects).
  • parseEftFit() leaves them out of the fit and says so: "Not applied, no longer available: Strokar Booster VI (an event booster that could be injected until 2026-08-26)..."; the engine skips them for any other source too.
  • The oracle (pyfa_fit_oracle.py) can't load them either (fit.notLoaded), as pyfa can't; compare_implants.py expects them not applied.

Verification

  • rupture_constructed_projectile_implants_boosters is now PYFA-VERIFIED against the owner's screenshot: 284 DPS, volley 1,048, 1.8 km + 14.4 km (14,358 m), EHP 8.72k (8,718), speed 262 m/s, align 5.71 s, signature 125, targeting 62.5 km, scan resolution 362 mm, sensor strength 18, capacitor 1.59k GJ. Its tally keeps the booster, so the pins also guard the engine's skip.
  • Speed: pyfa 262 m/s, page 263 m/s. Both are exactly 262.5 m/s; as with the Drake's 81.25 km targeting, pyfa's formatting rounds an exact tie to even.
  • Full output diff v.13 → v.14: only this fit changes. Update-check chain 21/21, suite ALL PASS, parse tests 293/293, compare_implants.py 0 of 13. Real page: 284 DPS, 1,048 volley, the note, and two boosters on the Fit card.

Lesson for future models

  • LESSONS_LEARNED #32 (new): pyfa's database is not the SDE. db_update.py deletes, unpublishes and patches items, and a reference built straight from the SDE inherits none of that. A count in pyfa's UI that differs from the paste is a finding.
