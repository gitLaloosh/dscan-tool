Propulsion module badge + per-type resistance breakdown

Date: 2026-10-10   Status: Delivered, verified via real captured ESI data + 28/28 regression PASS + byte-identical diff + real-Chromium checks

Requested by the owner: as the first step toward adding navigation speed to the Pilot Analyzer results, a badge next to the HP/DPS numbers identifying whether a fit carries an Afterburner, a Microwarpdrive, both, or neither — plus, separately, surfacing the fit's actual per-damage-type resistances, styled less prominently than the main effective-HP figure.

Correction found before shipping

The original plan was to detect Afterburner vs. Microwarpdrive by ESI/SDE group name, the same way every other module classification in this tool works. Checking this project's own already-captured real ESI data (golden_fits.json's groups cache, pulled from 13 distinct real AB/MWD item names across multiple golden fits) showed that premise was wrong: both module types share the exact same ESI group — group_id 46, group name "Propulsion Module." There is no group-name-based way to tell them apart.

Fixed by gating on group name ("Propulsion Module") and then splitting by an item-name substring check — "afterburner" vs. "warpdrive"/"warp drive" — which held across all 13 real sampled item names (T1, T2, faction, and meta variants alike). This is exactly the kind of thing this project's "verify against primary sources, never guess" rule exists to catch, and it worked as intended here before any code shipped with the wrong assumption.

The changes

Propulsion badge: the existing per-item classification loop that already scans every Mid/Low/Rig/Subsystem/High-slot item on a fit (for resist mods, Damage Controls, etc.) now also flags Afterburner/Microwarpdrive presence — zero new ESI calls, since those items were already being fetched. A new "Propulsion" stat block next to "Est. effective HP" and "Total DPS" shows "AB" / "MWD" / both / or "no afterburner/MWD fitted," with a note that this reflects what's physically fitted, not necessarily what was cycling at time of death (the same honest caveat as the Tactical Destroyer Mode badges) — the actual speed/align-time number is a separate follow-up phase, since it needs a new per-hull speed-bonus table (same complexity class as the existing SHIP_ROLE_BONUS/SHIP_RESIST_BONUS tables).

Per-type resistance breakdown: estimateHpAndDps() already computed each damage type's post-module/skill resistance internally (adjShieldRes/adjArmorRes/adjHullRes) to produce the averaged effective-HP figure, but never exposed the per-type values. Now surfaced as shieldResPct/armorResPct/hullResPct on the returned estimate (purely additive — no existing calculation touched) and rendered as a small, faded line under the existing shield/armor/structure HP breakdown, using the same damage-type badge styling already used elsewhere in the tool, deliberately smaller and lower-contrast than the main effective-HP number per your request. Only shown for a layer that actually has HP behind it (e.g. a pure shield tank's armor resists aren't shown, since 0 armor HP makes them meaningless).
