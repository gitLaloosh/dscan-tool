2. Bug found: FoF missiles missed the Auto-Targeting Missiles bonus

  • MAX_MISSILE_DAMAGE_MULT = 1.10 × 1.25 assumed every missile needs one skill with the missile damage effects (660/661/662/668, damageMultiplierBonus, 5%/level). pyfa applies every such skill the charge requires. Auto-Targeting (FoF) missiles require their size skill and Auto-Targeting Missiles (3322), so they get 1.25 × 1.25.
  • Fix: missileExtraSkillDamageMult(chargeDogma) counts the charge's required skills among the 7 SDE skills with those effects (all 5%/level). It is applied on both the loaded-ammo and the cargo-ammo paths.
  • The Raven FoF test fit goes from 45 to 57 DPS (pyfa 56.5) and volley from 386 to 483. Per shot: 281 × 1.10 × 1.25 × 1.25 = 482.97, on an 8.54 s cycle. This was the only fit that changed.

3. Rounding like pyfa

  • pyfa formats numbers with Python's round() (gui/utils/numberFormatter.py → roundToPrec). It rounds the exact binary value and sends an exact tie to the even digit. JavaScript sends ties up. So a speed of 262.5 m/s showed 262 in pyfa and 263 here; 81,250 m targeting showed 81.2 km in pyfa and 81.3 km here (both found earlier from the owner's pyfa screenshots).
  • pyRound(x, nd) is Python's round: it splits the value exactly into M / 2k and rounds with BigInt arithmetic. kmText(m) formats km.
    • Used for every rounded number estimateHpAndDps returns.
    • Also used for weapon ranges, drone / fighter / ammo breakdown DPS, EWAR chips and Misc flag texts.
    • Also used in the capacitor simulation (PYFA CORE cap-sim: cap_wrap = round(cap, 1) and the "%.1f" stable %). It was re-verified with compare_cap_sim.mjs (642 simulations, 0 mismatches) and its fingerprint updated.
  • Rounded once, from the raw value, as pyfa does: the km figures for targeting, drone control range and weapon ranges are now formatted from unrounded values. These are exact.* and the new rangeEstimates[].exactM, not the already-rounded metres.
  • Time to empty is truncated, as in pyfa: pyfa shows "%ds" / "%dm%ds" % divmod(t, 60), so 40.8 s shows "40s". The tool rounded. 21 of 82 unstable results in the golden set showed one second more than pyfa, e.g. the Rorqual without boosts showed 41s where pyfa shows 40s, and the Legion 1m56s where pyfa shows 1m55s. The new timeToEmptyExactSec (pyfa's sim.t / 1000) feeds the text.
  • The tool's own ranking values (missile application % and applied DPS) and the ring geometry keep Math.round; this is listed in DEVIATIONS.md.

Lesson for future models

  • LESSONS_LEARNED #4 (extended): a "max skills" constant is a hand table with one row. List every item it covers and check which skills each one requires.
  • #27 (extended): feed a whole-fit reference the tool's resolved inputs, not its own defaults. x or 1 turns a real 0 into 1. A reference that rounds must round like pyfa.
  • #34 (new): JavaScript rounds a tie up and pyfa rounds it to even. Round once from the unrounded value. Read how pyfa formats a stat (it truncates time to empty), not only how it computes it.
