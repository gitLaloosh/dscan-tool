Persistent ESI type/group cache (ARCH-3 fix) — Remediation Plan Phase 3

Date: 2026-10-10   Status: Delivered, 28/28 regression PASS, byte-identical before/after diff, verified in real Chromium with real IndexedDB

What this fixes

ARCH-3 (logged 2026-10-09): getType()/getGroup() only cached ESI lookups in an in-memory Map, cleared on every page reload. Ship/module dogma data is close to static — it changes a few times a year via CCP balance patches — but was being re-fetched live from ESI on every single analysis, which is unnecessary latency and network-dependency for a tool meant for quick in-the-moment threat assessment.

The fix

Added an IndexedDB-backed persistent cache layer in front of the existing live ESI fetch inside getType()/getGroup():

  • A lookup first checks the existing in-memory Map (unchanged), then the new IndexedDB store. A hit still within a 7-day TTL returns straight from IndexedDB with zero network call.
  • A miss or an expired entry falls through to the exact same live ESI fetch as before, then writes the fresh result back to IndexedDB for next time.
  • A new "Refresh item data" button in the header (wired to a new clearDscanCache()) wipes both the IndexedDB store and the in-memory Maps outright — for immediate use right after a known balance patch, without waiting out the TTL.

This only changes where the data comes from, never what comes back — getType()/getGroup() return the identical JSON shape either way, so it cannot touch any DPS/EHP math. Every persistent-cache operation is wrapped so a missing or broken IndexedDB (private browsing, an old browser, a quota error) silently degrades to the pre-Phase-3 behavior — live fetch every time, cache simply never populated — rather than breaking analysis.

Why the regression suite is unaffected

run_regression.mjs executes this whole script in a Node vm sandbox that has no indexedDB global at all. typeof indexedDB === 'undefined' is therefore true there, so openDscanCacheDb() resolves to null immediately and getType()/getGroup() fall straight through to the (mocked) live fetch — exactly the same code path as before this change. That's why the regression suite's console output is byte-identical before and after.

Files/functions changed

  • New: openDscanCacheDb(), dscanCacheGet(), dscanCacheSet(), clearDscanCache() — declared near the existing typeCache/groupCache Maps.
  • getType() / getGroup() — each gained one persistent-cache check between the existing in-memory-Map check and the existing live fetch, and one fire-and-forget persistent-cache write after a successful fetch. No other logic touched.
  • New header control: #refreshCacheBtn ("Refresh item data") + #cacheStatus status line, wired to clearDscanCache().
