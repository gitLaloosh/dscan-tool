Subtext rule, phase S1: info panel, reserved Reset, set-width numbers

DesignFix 2026-10-24 · v2026.10.14.47 → v2026.10.14.48. Plan: roadmap/subtext-plan.md; mockup on the layout canvas, page "Subtext rule".

the owner (2026-10-24): "the subtext in the tool is a little overwhelming and distracts from important values ... address it as a site wide design choice", and "when making changes to the damage application slider, numbers change on multiple cards which causes the content to shuffle and move elements on the page". Decided: "works as written. info icon opens a panel over the page. the 40 character limit is fine." This first phase builds the pieces every card will use, and fixes the two things measured to move the page.

What changed on the page

  • Info button on the Damage Application card. The card's grey method paragraph ("As pyfa's damage graph: …") is gone from the card. It now opens from an ⓘ button in the card's title row, in a panel over the page. The panel is a sheet from the bottom on a phone. Escape, a press outside it, or its close button close it. A "Not in the chart yet: …" warning still shows under the chart when something isn't charted.
  • Reset is always there. It's an icon button next to ⓘ: enabled once a setting moves, disabled at the defaults. It used to appear as a text button once a setting moved, which made the card 16 px taller and pushed the whole page down (42 px on a phone).
  • Numbers keep their width. The headline DPS and the four Matchup numbers sit in boxes as wide as the widest value they can show, so the second number in a Matchup half no longer slides when the first changes ("26 s" → "1 min 7 s"):
    • DPS: the fit's raw DPS plus 2%, since wrecking hits average 1.5% above raw;
    • times: "over an hour".
  • Fix: "Adjust" with no sliders (the owner's earlier screenshot). The card opens Adjust only when it is at least 720 px wide. A Pilot loss tab that isn't shown is drawn with no width (0), so Adjust started closed, and on the wide layout that left an "Adjust" heading with nothing under it. A card that isn't laid out yet now judges by the window width.

No calculation changed.

The shared pieces (for phases S2 and S3)

  • CARD_INFO: each card's info-panel text, by card key, as plain paragraphs. It sits next to CARD_NAMES, and is JSON so the tools can read it.
  • infoBtnHtml(key): the ⓘ button and its panel. It reuses the Last Kill panel's style and the page-wide Escape / outside-press closer, which now also closes info panels.
  • ctxHtml(text): the one-line context slot. 11.5 px in --text-dim, one line, cut with "…" and shown whole on hover.
  • numBoxStyle(widest): a live number's set width.

New checks

  • tools/check_subtext.py (update-check chain, now 36 steps). It fails on:
    • a context line in the code over 40 characters;
    • an info button without CARD_INFO text, or CARD_INFO text that's never shown or isn't a card key.
    It reports (doesn't fail yet) the 29 CSS rules that colour text with the too-faint grey.
  • tools/page_checks/no_shift_check.py: uses every Damage Application control at 1440, 1100 and 375 px and measures every card. It fails if the Matchup board or the Damage Application card moves (wide layouts), and reports what else still moves:
    • the Weaknesses card grows up to 42 px when the picks text changes, and the cards below it follow (phase S2);
    • on a phone, the Damage Application headline still re-wraps as its sentence changes (phase S2).
    On v.47 it fails exactly where expected: the card moved 16 px with Reset appearing.
  • damage_chart_check.py: Reset enabled/disabled; the method text off the card and in the panel; the panel doesn't change the card's height; Escape and an outside press close it; the phone sheet and its close button; Adjust open on a loss tab that was hidden when drawn.

Verification

  • Regression suite ALL PASS; update-check chain all 36 steps OK; every page check 0 failures.
  • The new checks fail on v.47 and pass on v.48.

Lesson for future models

Two mistake classes, LESSONS #44 and #45.

  • Reserve space. A control or line that appears only after the user changes something moves everything below it. Reserve its space from the start: show it disabled, and give live numbers a fixed width. Then measure before and after using each control, because a screenshot of either state looks fine.
  • Hidden means width 0. A size measured while the element is hidden (an inactive tab) is 0. Check whether it can be hidden before trusting it.
