  • The layout table FIT_LAYOUT (block // ==== FIT LAYOUT TABLE):
    • stacks: the cards in each column, top to bottom;

    fitSummaryParts() now returns each card on its own, fitLayoutHtml() stacks them from the table, and fitLayoutGridCss() writes the grid stylesheet from it at load. The old fixed grid rules are gone from the stylesheet. Moving a card, or changing how many columns it spans, is now an edit to the table. The table is also what a later "Edit layout" mode would change.
  • LESSON #38 is enforced in code. fitLayoutGridCss() throws if any area sits below the sticky Fit column from 900 px up, or if a row has the wrong number of areas. Both cases were tested.
  • The card sizes itself by its own width (a container query at 720 px). With room, the sliders sit beside the chart; in a narrow column they fold under "Adjust", closed. That makes any of the three placements work.

Lesson for future models

When a layout rule matters (here: nothing below a sticky column), put it where the layout is defined and make it fail loudly, not just in a document. Writing the grid from a table made that possible: the rule is a few lines in fitLayoutGridCss(), and the page check scrolls through the layout to catch anything the rule misses.
