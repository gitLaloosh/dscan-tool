Volley damage stat

Date: 2026-10-10   Status: Delivered, verified via 29/29 regression PASS + an EXACT match against a real pyfa report + a real-Chromium render check

Requested by Erik: "volley stats would probably be good to have along w/ dps in the tool" — prompted by comparing the tool's output against a real pyfa report for the newly-scaffolded Loki fit (killmail 138935092), which showed pyfa's own "Volley: 1349" line alongside its DPS.

The change

Each fit's "Total DPS" stat now shows a second line, "Volley <number>", whenever it's nonzero: the one-shot/one-cycle total damage across every CERTAIN damage source (confirmed-loaded turrets/launchers, fixed-damage weapons, deployable drones, deployable fighter squadrons) — the exact same source set dpsFixed already covers, just without dividing by each source's own cycle time. A weapon only resolved via the cargo-ammo guess doesn't contribute (same scoping as dpsFixed itself).

Checked pyfa/eos's own source before assuming scope (eos/stats/register/dmg_dealer.py's DmgDealerRegister.get_volley()): it sums every damage-dealing item's own get_volley() with no category exclusion, confirming drones and fighters genuinely do count toward pyfa's Volley stat, not just turrets/missiles — this was worth checking rather than assuming, since EVE players colloquially think of "volley"/"alpha" as a turret/missile-only concept.

Each of the four existing DPS-computation blocks (drone, fighter, fixed-weapon, confirmed-ammo turret/launcher) already computed an intermediate "damage per cycle" value before dividing by cycle time to get DPS — this change just also accumulates that same intermediate value (times quantity/deployed-count) into a new volleyFixed total. Zero new ESI calls, zero new multipliers/skill constants — pure reuse of already-verified building blocks.
