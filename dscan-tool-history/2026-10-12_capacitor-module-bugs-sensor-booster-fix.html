Capacitor module backlog + Sensor Booster/Signal Amplifier fix

2026-10-12 · index.html · from the full module-dogma-audit, KNOWN OPEN ITEMS #1–#5 · Erik: "work on the bug list"

Four of the five remaining real bugs from the module-dogma audit, all re-verified directly against the local pyfa SDE cache (primary source, not the audit's own notes) before fixing. The fifth (Golem torpedo Bastion RoF ratio) has no new avenue since its last investigation and was left open.

#1: Power Diagnostic System / Shield Power Relay not gated into the capacitor fix

Both carry attribute 144 (capacitorRechargeRateMultiplier), the same attribute the existing Capacitor Power Relay/Flux Coil/Recharger fix already pools — but neither module's group name was in that gate. Power Diagnostic System II (attr144=0.915, a reduction — slots into the existing pool) also carries attr147=1.05, an increase to capacitor capacity, the opposite direction from Capacitor Flux Coil's own attr147 (a cut) — needed its own bonus-direction pool (capCapacityBonusFractions). Shield Power Relay II carries attr144=1.35, a cap-recharge penalty — also the opposite direction from every existing module in that group, needing its own penalty pool (capRechargeTimePenaltyFractions). Both modules' real shield-side attributes (134/146/338) are left unmodeled, since passive shield recharge isn't tracked anywhere in this file yet (separate open feature-backlog item).

#2 / #5: Shield Boost Amplifier / Capacitor Power Relay shieldBoostMultiplier

Both carry attribute 548 (shieldBoostMultiplier) — Shield Boost Amplifier II as a +36% bonus, Capacitor Power Relay II as an -11% penalty (its own real tradeoff for the recharge-rate gain already modeled). Neither was ever read. Applied as one ship-wide multiplier on the aggregate shieldRepHpPerSec total after the module loop, stacking-penalized by direction (bonus pool vs. penalty pool, same split convention as #1 above).

Caught a real regression on delivery: golem_zkb138991664_bastion (a real killmail) carries a Republic Fleet Shield Boost Amplifier + Gist A-Type X-Large Shield Booster. Its pinned shieldRepSustainedDps was 171 — the bare Shield Booster rate (682 HP / 4s = 170.5), with the Amplifier's +36% silently dropped. Hand-verified the fix's new output (232 = 170.5 × 1.36) against the module's own real dogma attributes and corrected the golden fit's expectation in place, same pattern as the earlier Caracal "22% high" correction.

#4: Capacitor Battery's energyWarfareResistanceBonus unmodeled

Capacitor Battery II carries attr2267=-25 (25% resistance to incoming Energy Neutralizer/Nosferatu). This is a defensive stat about the ship being analyzed — not applied to that ship's own outgoing neut/nos figures in the EWAR card, which stay unresisted by design (a broader, disclosed scope limit unrelated to this fix). Surfaced as a new capacitor.warfareResistPct field and a new line in the Capacitor card, shown only when a Capacitor Battery is actually fitted.

#3: Sensor Booster/Signal Amplifier/Remote Sensor Booster bonus not folded into sensorStrength

All three carry the same 4 racial scan-strength attributes (1027–1030, e.g. +48% on Sensor Booster II/Signal Amplifier II). Checking each module's real dogma effect (not just its attributes) turned up a methodology correction to the original audit item, which had lumped all three together:

ModuleReal effectTreatment
Signal AmplifierscanStrengthBonusPercentOnlineGenuinely passive — applies whenever fit+online. Fixed, applied unconditionally.
Sensor BoostersensorBoosterActivePercentageRequires activation. Fixed, assumed active whenever fitted — same standing convention this file already uses for Bastion/Siege Module/MWD.
Remote Sensor BoosterremoteSensorBoostFalloff (isAssistance:1)Buffs a locked target, not the fitting ship's own sensor strength. Deliberately excluded — including it would have been a straightforward false positive, not a fix.

Fixed by folding Sensor Booster's/Signal Amplifier's own bonus into the existing per-type scan-strength pool, stacking-penalized against each other and layered on top of (not combined with) the existing Sensor Compensation skill multiplier.
