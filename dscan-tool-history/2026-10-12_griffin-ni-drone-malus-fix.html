Griffin Navy Issue drone-damage/control-range malus fix

2026-10-12 · dscan-tool.html · KNOWN OPEN ITEM #3 in dscan-tool.md: "a real, entirely-unmodeled mechanic -- the tool has no concept of a malus, only bonuses"

The gap

The tool's role-bonus mechanism (SHIP_ROLE_BONUS) has always been capable of negative percentages -- the multiply at dmgMult *= (1 + bPct/100) works correctly for a negative bPct with zero code changes -- but no hull had ever actually been given one. The Griffin Navy Issue is the one real example confirmed live: its own dogma carries two negative role-bonus attributes that were never added to the table, so the tool silently treated it like any other ship with no drone malus at all.

Root cause, grounded

Fetched Griffin Navy Issue's (type 37455) raw dogma_attributes live via ref-data.everef.net:

AttributeValueMatches everef Traits text
2091-70.0"-70% Drone damage" (Misc. drawback, FLAT, not skill-scaled)
2298-50.0"-50% reduction in Drone hitpoints and control range" (same)

The existing table entry for this hull ("37455":[["hybrid","damage",100]], its +20%/lvl Small Hybrid Turret bonus at V) only ever carried the positive turret bonus -- the two negative drawbacks were never added.

Fix

Drone damage (-70%): added directly to the existing SHIP_ROLE_BONUS entry -- ["drone","damage",-70]. No new mechanism needed; the per-category dmgMult multiply already handles a negative bPct correctly (confirmed by inspection and by this fix's own golden fit).

Drone control range (-50%): a genuinely different shape -- a multiplier on the ship's *total* control range, not a flat km add like the existing SHIP_DRONE_CONTROL_RANGE_BONUS table (Ishtar's own +25km elite bonus). New SHIP_DRONE_CONTROL_RANGE_PENALTY_MULT table, applied as a final multiplicative stage after the existing additive base+skill+module+ship-bonus sum. The Navigation & Targeting card's breakdown sub-text now appends a "X% hull role bonus PENALTY applied" note whenever this multiplier isn't 1, so the breakdown stays honest (the additive parts no longer sum to the displayed total on this one hull).

Drone hitpoints (-50%): explicitly NOT modeled -- the tool has never tracked drone HP for any ship (confirmed via code search, zero references anywhere), so there's nothing for this half of the role bonus to attach to. Disclosed, not silently dropped.

Verification

New golden fit griffin_navyissue_constructed_drone_malus (bare Griffin NI hull + 10x Hobgoblin II in the drone bay, no other modules), sandbox-verified against the live post-fix code:

StatPre-fixPost-fixRatio
Drone DPS (5 deployed)99300.30x (exactly the -70% malus)
Drone control range60,000 m30,000 m0.50x (exactly the -50% malus)

Hand-derivation: dmgPerCycle = 20(thermal) × 1.92(Hobgoblin II's own multiplier) × 2.0625(Drone Interfacing × Light Drone Operation × Gallente Drone Specialization, all V) × 0.30(this fix) = 23.76; perDroneDps = 23.76/4s = 5.94; droneDps = 5.94 × 5 deployed = 29.7, rounds to 30 -- exact match to sandbox output.

Pre-fix, the tool was overestimating this hull's drone DPS by a factor of ~3.3x (99 vs. the real 30) -- a much larger error than the open item's original "Moderate scope" framing suggested, now that the actual magnitude is confirmed. Drone control range was overestimated 2x (60km vs. the real 30km), which would also mis-inform threat assessment of how far out this hull's drones can be sent.

Scope

Only the Griffin Navy Issue is affected -- this is the one hull in the entire table confirmed to carry a negative drone role bonus; no sweep of other hulls for similar negative bonuses was done (out of scope for this narrow, single-hull fix per the project's own "narrow discrepancy -> go straight to that item's own dogma, skip the full exhaustive sweep" policy). Drone hitpoints remain unmodeled for every ship, same as before.
