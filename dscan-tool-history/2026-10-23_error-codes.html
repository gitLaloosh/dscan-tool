Error codes that point back to why each message exists

Maintenance 2026-10-23 · v2026.10.14.31 → v2026.10.14.32 · the owner: "should we have identifiers for custom error codes that point back to why we implemented them?", then "ok do it".

What changed

  • Every error the page writes now ends with a short code, for example "… Try again in a few minutes. (ZKB-01)". Prompts for an empty box ("Enter a pilot name.", "Paste a fit first.") have no code: they're instructions, not errors.
  • ERROR_CODES in index.html is the one place a code is defined. Each entry gives the title, where it shows, what triggers it, what to check, why the message exists, the build or date that added it, and its history doc when there is one. Helpers: withCode(text, code), codedError(code, message), and errorCodeOf(e), which returns APP-01 for any error without a code (an unexpected error, i.e. a bug).
  • ERRORS.md (repo root) is generated from the registry by tools/gen_errors_md.py. Without --write, the script fails when a code is used but not listed, listed but never used, or missing a field, or when ERRORS.md is out of date. It's in the update-check chain, now 27 steps.
  • Rules, written in ERRORS.md and CLAUDE.md: never reuse or renumber a code; a retired error keeps its row, marked retired.

Where a message's origin predates the history log, the registry says "original (before 2026-10-08)" rather than guessing.

Small wording changes

  • The generic catch-alls ("Error: …") now end with a period before the code.
  • DSCAN-02 no longer adds "check your network connection", since the likely cause is the paste.
  • The last-kill box shows the underlying code: ESI-05, ZKB-01/03 or PILOT-07.

Lesson for future models

  • When the owner reports an error, ask for the code and the version tag, then start from that code's row in ERRORS.md. When you add an error, register its code first. The check fails on a code that's used but not registered. An error thrown without a code shows APP-01; treat any APP-01 report as a gap to fix.
