PANIC: Active option removed, flag duration fixed

UIBug fix 2026-10-14 · v2026.10.14.9 → v2026.10.14.10 · follow-up to bug list #2

Why

v.9 let the PANIC be set active on the Fit card, as the owner's bug report asked. the owner then asked whether the option should exist at all, since he had assumed activating it would change the cards' numbers. It didn't: pyfa has no handler for the PANIC's effect (6719), so pyfa computes nothing for it, and CCP's buff values for it aren't in pyfa's data. the owner: "if a user sets it to active and sees nothing change they may think that the tool isn't working properly." Agreed: a control that changes nothing looks broken.

What changed

  • The PANIC follows pyfa again: offline or online, no Active state (hover: "Can't be active: has no active function"). ACTIVATABLE_WITHOUT_PYFA_HANDLER_EFFECTS and the PANIC's entry in MODULE_DEFAULT_ONLINE_EFFECTS were removed; the DEVIATIONS.md row is gone. Module states are now exactly what v.8 produced.
  • The EWAR / Misc flag stays and always reads the same: "can activate to make this Rorqual and its fleet's subcapital mining and hauling ships within 200 km nearly invulnerable for 6 min, but none of them can deal damage, warp, dock, cloak or jump while it runs. One use, then it burns out. Not reflected in the stats (pyfa doesn't model it)".
  • Duration fixed, 4 → 6 minutes. v.9 quoted the item's base value. The Invulnerability Core Operation skill (44067; "10% increase per level to the effect duration") is applied by pyfa's Effect6807 to buffDuration (attr 2535): at All V, 240 s × 1.5 = 360 s. The flag now reads buffDuration × MAX_INVULNERABILITY_CORE_OPERATION_MULT (1.5).

Verification

  • tools/independent_checks/check_panic.py rewritten first: pyfa can't activate the PANIC; it is still the only published module of its kind; pyfa's handlers at All V give buffDuration 360,000 ms and range 200 km; a PANIC online changes no Rorqual attribute. 0 problems.
  • Both PANIC goldens re-pinned before the code (6-minute wording; the "requested active" fit now pins the refusal). Both fail on v.9 and on v.8.
  • Full output diff v.8 → v.10: the same 4 PANIC fits differ, and only by the new flag.
  • Regression suite ALL PASS, parse tests 293/293, update-check chain 17/17 OK.
  • Real page: the PANIC button cycles online ↔ offline; the flag shows when online and disappears when offline.

Lesson for future models

LESSONS_LEARNED #29 (revised): if pyfa doesn't model something, don't add a control that changes nothing. Describe it in words where it matters and say the stats don't include it, and ask before adding an input whose only effect is a label. Any number a flag quotes goes through pyfa's handlers at All V like every other stat, not straight from the item's base attribute (#20).
