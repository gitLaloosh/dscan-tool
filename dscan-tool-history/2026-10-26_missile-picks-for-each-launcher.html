The Missile tile: the best ammo for each launcher

FeatureFixTests 2026-10-26 · v2026.10.14.68 → v2026.10.14.69.

The owner asked about the backlog item "Missile ammo pick uses raw charge stats" (optional phase 5 of the hand-table work).

  • That item was already done in v.27: the pick uses your two application skills at V, pyfa's only skill handlers on a missile's application.
  • What was left was presentation. The tile picked one ammo across every launcher size, so a battleship target got "Torpedo" even for a frigate pilot.

The owner's decisions:

  • "let's do #3": show a pick for each launcher size;
  • from the mockup (the real page, desktop and phone), option A: six rows rather than three sizes;
  • "Keep it" for the column with the target's prop module on.

What you see

This applies to the Weaknesses card with no ship saved; with My Ship on, your own picks replace these tiles as before.

  • The label reads "Missile · Nova", the damage type's race prefix.
  • One row per launcher: Rocket, Light, HAM, Heavy, Torpedo, Cruise. Each row shows the best ammo tier (T1, Fury, Precision, Rage, Javelin) and how much of its damage lands.
  • Columns "MWD off / on" ("AB" for an afterburner), when the target fits a prop module. The "on" column names a tier only when a different one is better there: against a Megathron with its MWD on, Cruise switches from T1 to Precision.
  • Colour: under 50% is amber.
  • Hover gives the full ammo name and both percentages to one decimal, e.g. "Inferno Precision Light Missile: 100% of its damage lands with their MWD off, 100% with it on."
  • Narrow screens: at 320 px the tile still fits. The "on" column's tier is cut first ("P…", whole on hover).

Found on the way: afterburner fits had no "prop on" missile ranking

  • The bug: the prop-on ranking was computed only when the target had an MWD signature bloom (boostedSignatureRadius, MWD only). A target with an afterburner had a boosted speed but no ranking, since v.27.
  • The fix: the prop-on state is now the winning prop module's speed with its own signature: an MWD's bloom, or an afterburner's base signature.
  • Effect: 32 existing golden fits with an afterburner gained a prop-on ranking (33 with the new one); no pinned number moved. The independent check went from 286 to 319 rankings, 0 mismatches.

Lesson for future models

LESSON #64: a state gated on one variant's attribute silently drops the other variants.

  • "Prop on" was gated on the MWD's signature bloom, so afterburner fits never had it. The check skipped the state because the tool said it was absent.
  • Gate a state on what defines it (a prop module is fitted), and give each variant its own value.
  • When a check skips a state, also check that the tool should leave it out. Add a golden fit for each variant.
  • For a recommendation: rank inside the choice the user actually has (their launcher). A single pick across choices they can't make isn't an answer.
