# tools/ — verification tooling for EVE Threat Assessment (ETA) calculations

Everything here reads **primary sources only**: pyfa's real source code
(`eos/effects.py`) and CCP's SDE, which pyfa ships under `staticdata/fsd_built/`.
Nothing here reads `index.html`'s tables, except where a script compares
against them on purpose (`gen_weapon_range_table.py`).

Read `../LESSONS_LEARNED.md` first. It explains why these tools exist.

## Setup (no pip installs needed)

```
git clone https://github.com/pyfa-org/Pyfa  /some/path/Pyfa   # verified with v2.69.3, SDE build 3624425 (2026-10-21)
export PYFA_SRC=/some/path/Pyfa
python3 -I tools/gen_weapon_range_table.py index.html
```

`-I` (isolated mode) is deliberate. The scripts set their own import paths.

## Files

| File | What it does |
|---|---|
| `pyfa_sde.py` | Loads the SDE from pyfa's dump. `pyfa_removed_types()` (v2026.10.14.14, LESSON #32): the type ids pyfa's `db_update.py` deletes (expired event boosters) or unpublishes, i.e. what pyfa itself can't load. `A('Rokh')` returns an attribute dict by name; `reqs(typeId)` returns the direct required skills (what pyfa's `requiresSkill` checks). |
| `pyfa_effects.py` | **Runs pyfa's real effect handlers** against a recording mock fit. It tells you exactly which attribute a handler changes, from which source attribute, with which skill scaling, and whether it is stacking-penalized and in which penalty group. `filter_hits()` evaluates the handler's filter against real SDE items. For skill effects pass `carrier=skillTypeId` (LESSON #19). Use this instead of regex-reading `effects.py`. `run(..., rich=True)` (v2026.10.14.8) also records `fit.character.getSkill`, `fit.ship.item.requiresSkill` and `fit.extraAttributes` as values and conditions; read every handler error a run reports (LESSON #28). |
| `audit_effect_tables.py` (+ `dump_effect_tables.mjs`) | Runs every pyfa handler and compares with `index.html`'s capacitor, HP, sensor, repair, shield-recharge and signature tables. Prints MISSING / EXTRA / ROW MISSING / FILTER, PENALTY or LEVEL DIFF, plus skill rows. Deliberate exclusions live in its `KNOWN` list with reasons. Run: `node tools/dump_effect_tables.mjs index.html > /tmp/t.json && python3 -I tools/audit_effect_tables.py /tmp/t.json`. A clean run prints no MISSING/EXTRA/DIFF lines. |
| `gen_module_state_tables.py` | Regenerates `EFFECT_STATE_TYPE` (which effects are active/offline/overheat), `GROUP_LIMIT_MOD_EFFECTS` (maxGroupActive/Online modifiers) and `ACTIVATION_BLOCK_EFFECTS` from pyfa's handler types and recorded calls, and diffs them with `index.html`. Re-run after a pyfa/SDE update. |
| `cap_sim_oracle.py` | Runs pyfa's own `eos/capSim.py` (standard library only, imported straight from the pyfa checkout) on drain lists, with `Fit.__runCapSim()`'s settings. The reference for `capSimPyfa()` in index.html; `regression_suite/compare_cap_sim.mjs` feeds it every golden fit's `capacitor.simInputs` and requires zero mismatches. |
| `gen_weapon_range_table.py` | Worked example: regenerates `WEAPON_RANGE_MOD_EFFECTS` and diffs it against `index.html`. Copy it as the template for any "every handler that changes attribute X" table. Re-run it after a pyfa/SDE update to see what changed. Since v2026.10.14.34 it also covers the damage-application attributes (turret tracking, missile and Vorton explosion radius / velocity) and `--write` rewrites the embedded table (then re-lock with `check_pyfa_core.mjs --update`). |
| `gen_hull_damage_table.py` | Regenerates `SHIP_DAMAGE_MOD_EFFECTS` (PYFA CORE `hull-damage`): every hull and subsystem handler on weapon damage/RoF, charge damage per type, drone and fighter damage, with exact filters (skills/groups on the weapon or the charge -- it tests every charge x weapon pairing, LESSON #22) and damage types. Since v2026.10.14.4 also writes `FIGHTER_ABILITY_EFFECTS` (each fighter ability effect -> modeled target + attribute ids), prints the abilities pyfa switches on by default per fighter class, and asserts every damaging default ability is modeled. Diffs against index.html; `--write` embeds. Lists skipped pilot-dependent values and attributes no pyfa ability reads. Re-run after a pyfa/SDE update. |
| `pyfa_fit_oracle.py` | **Runs pyfa's own handlers on a whole fit** (hull, modules with charges and states, All 5 skills, Tactical Destroyer / Anhinga mode) with a hand port of `modifiedAttributeDict.__calculateValue` (stacking groups, forced values, max caps, SDE defaults). `OracleFit('Paladin', [('Bastion Module I','active'), ('Damage Control II','online')]).calculate().ship.get('armorEmDamageResonance')`. The reference for resistances since v2026.10.14.5; validated against the owner's pyfa screenshots. Implants and boosters since v2026.10.14.12 (`implants=` / `boosters=`, run between the ship and the modules as pyfa orders them; booster side effects off). Drones in space since v2026.10.14.13 (`drones=[(type, amountActive)]`); `fit.extraAttributes` is the ship's attribute dict with pyfa's `Ship.EXTRA_ATTRIBUTES` (drone control range starts at 20 km). Not modelled: fighters, projected/command effects. Since v2026.10.14.35 every modifier records which item made it (`Attrs.afflictions`) and `Attrs.extended(key, extraMultipliers, ignoreAfflictors)` is a hand port of pyfa's `getExtended` / `__calculateValue` (used by `check_projected.py`). Every `AttributeError` naming one of its own stand-in classes is kept in `fit.oracleGaps` (pyfa swallows AttributeErrors, so a missing stand-in method would otherwise skip a handler silently; LESSON #27) -- must be empty. Ships carry mass/capacity/volume/radius as attributes, as in pyfa's database. |
| `gen_resist_table.py` | Regenerates the PYFA CORE `resist-calc` tables: `RESIST_EFFECTS` (every hull/module/charge/mode handler on ship resonances or a module's own resist attributes, with operation and stacking group), `RESIST_SKILL_MODULE_ROWS` (Compensation skills), `RESIST_ATTRS`, `MODE_ITEMS`. Diffs; `--write` embeds. Reports skipped carriers (beacons, implants/boosters, fighters, overheat). |
| `gen_mode_table.py` | Regenerates the PYFA CORE `modes` table `MODE_EFFECT_ROWS`: every effect of every ship mode item (Tactical Destroyers incl. the Skua, and the Anhinga) run through pyfa's handlers, with the value resolved from the mode item, the stacking group and the module/charge filter (skills AND groups, asserted exact). Asserts each penalized row is alone in its stacking group. Resonance rows are skipped (they're in `RESIST_EFFECTS`). Diffs; `--write` embeds. |
| `gen_speed_table.py` | Regenerates the PYFA CORE `speed-calc` tables: `SPEED_EFFECTS` (every hull/module/rig/subsystem handler on ship maxVelocity/agility/mass and on the module attributes they read), `SPEED_SKILL_ROWS` (one row per skill, value at V, with hull-skill conditions), `SPEED_ATTRS`, `SPEED_PROP_EFFECTS`, `SPEED_CLOAK_EFFECTS`. Two passes: module attributes ship rows read get their own modifiers recorded (rig drawbacks, plate mass). Fails if pyfa's Effect6730/6731 source changes (`speed_prop_effects.sha256`; re-check `pyfaPropBoost`, then `--record-prop-source`). Diffs; `--write` embeds; `--verbose` lists rows and every handler error (LESSON #28). |
| `gen_ewar_table.py` | Regenerates the PYFA CORE `ewar-calc` tables (v2026.10.14.11, hand-tables P4): `EWAR_EFFECTS` (every hull/module/rig/subsystem/script handler on an EWAR module's own range, falloff, strength or neutralizer/nosferatu amount; scripts are `'self'` rows on their own module), `EWAR_SKILL_ROWS`, `EWAR_ATTRS`, `EWAR_GROUPS`. Lists every handler error; fails on a filter it can't express or an order-dependent runtime. `--write` embeds, `--verbose` prints rows and skips. |
| `gen_implant_table.py` | Regenerates the PYFA CORE `implant-calc` tables (v2026.10.14.12): `IMPLANT_EFFECTS`, every implant and booster effect run through pyfa's handler in its carrier's own context (`'implant'` / `'booster'`; handlers branch on it), with exact (skills AND groups) filters on modules, charges, drones, fighters and other implants (set bonuses, asserted early unpenalized multiplies). Booster side effects skipped (pyfa's default is off). Diffs; `--write` embeds. |
| `pyfa_update_check.py` | **Run first in every session.** Compares the manifest's verified pyfa version/commit/SDE build with the local `PYFA_SRC` and GitHub; `--run` runs the whole verification chain (core lock, golden-fit refresh report, generators incl. the mode table, effect audit, capSim comparison, suite, resists and modes vs pyfa's handlers). See `PYFA_CORE.md`. |
| `check_pyfa_core.mjs` (+ `pyfa_core_manifest.json`) | The PYFA CORE lock: checks every `PYFA CORE BEGIN/END` section of `index.html` against its recorded SHA-256. The regression suite runs it first. `--update` records new fingerprints, only after running that section's `verify` commands. |
| `audit_firepower.py` | Since v2026.10.14.3: checks that the `SHIP_ROLE_BONUS` fallback lists only hulls with no pyfa damage effect, plus modules, skills and drone range (hulls/subsystems are covered by `gen_hull_damage_table.py`). Originally: runs every pyfa handler that changes weapon, drone or fighter **damage or rate of fire** (hulls incl. unpublished special editions, subsystems, modules, rigs, skills) and diffs it against `SHIP_ROLE_BONUS`, `SUBSYSTEM_ROLE_BONUS`, `MODULE_DAMAGE_GROUP_CATEGORY` and the skill constants. Run: `node tools/dump_effect_tables.mjs index.html SHIP_ROLE_BONUS,SUBSYSTEM_ROLE_BONUS,... > /tmp/fp.json && python3 -I tools/audit_firepower.py /tmp/fp.json` (full table list in its docstring). Read LESSON #22 before trusting a mismatch. |
| `refresh_golden_fixtures.py` | Refreshes every golden fit's type and group records from the SDE (merge: SDE values win, fixture-only attributes kept). Report mode (no `--write`) is the **completeness check**: a fully refreshed file prints `0 of N fits change`. Run it after adding a golden fit or updating pyfa/SDE, then rerun the suite and explain every number that moves (LESSON #6). Keeps `golden_fits.json`'s compact serialization. |
