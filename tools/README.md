# tools/ — verification tooling for EVE Threat Assessment (ETA) calculations

Everything here reads **primary sources only**: pyfa's real source code
(`eos/effects.py`) and CCP's SDE, which pyfa ships under `staticdata/fsd_built/`.
Nothing here reads `index.html`'s tables, except where a script compares
against them on purpose (`gen_weapon_range_table.py`).

Read `../LESSONS_LEARNED.md` first. It explains why these tools exist.

## Setup (no pip installs needed)

```
git clone https://github.com/pyfa-org/Pyfa  /some/path/Pyfa   # verified with v2.69.3, SDE build 3624425 (2026-10-21)
export PYFA_SRC=/some/path/Pyfa
python3 -I tools/gen_weapon_range_table.py index.html
```

`-I` (isolated mode) is deliberate. The scripts set their own import paths.

## Files

| File | What it does |
|---|---|
| `pyfa_sde.py` | Loads the SDE from pyfa's dump. `A('Rokh')` returns an attribute dict by name; `reqs(typeId)` the direct required skills (what pyfa's `requiresSkill` checks); `pyfa_removed_types()` (v2026.10.14.14, LESSON #32) the type ids pyfa's `db_update.py` deletes or unpublishes, i.e. what pyfa itself can't load. |
| `pyfa_effects.py` | **Runs pyfa's real effect handlers** against a recording mock fit: which attribute a handler changes, from which source attribute, with which skill scaling, and in which stacking-penalty group. `filter_hits()` evaluates the filter against real SDE items. Skill effects: pass `carrier=skillTypeId` (LESSON #19). `run(..., rich=True)` (v2026.10.14.8) also records getSkill / requiresSkill / extraAttributes; read every handler error (LESSON #28). Use instead of regex-reading `effects.py`. |
| `audit_effect_tables.py` (+ `dump_effect_tables.mjs`) | Runs every pyfa handler and compares with `index.html`'s capacitor, HP, sensor, repair, shield-recharge and signature tables; prints MISSING / EXTRA / ROW MISSING / FILTER, PENALTY or LEVEL DIFF. Exclusions: `KNOWN`, with reasons. Run: `node tools/dump_effect_tables.mjs index.html > /tmp/t.json && python3 -I tools/audit_effect_tables.py /tmp/t.json`. A clean run prints no MISSING/EXTRA/DIFF lines. |
| `gen_module_state_tables.py` | Regenerates `EFFECT_STATE_TYPE` (which effects are active/offline/overheat), `GROUP_LIMIT_MOD_EFFECTS` (maxGroupActive/Online modifiers) and `ACTIVATION_BLOCK_EFFECTS` from pyfa's handler types and recorded calls, and diffs them with `index.html`. Re-run after a pyfa/SDE update. |
| `cap_sim_oracle.py` | Runs pyfa's own `eos/capSim.py` (from the pyfa checkout) on drain lists with `Fit.__runCapSim()`'s settings. The reference for `capSimPyfa()`; `regression_suite/compare_cap_sim.mjs` feeds it every golden fit's `capacitor.simInputs` and requires zero mismatches. |
| `gen_weapon_range_table.py` | Worked example and template for any "every handler that changes attribute X" table: regenerates `WEAPON_RANGE_MOD_EFFECTS` (ranges plus, since v2026.10.14.34, tracking and explosion radius / velocity) and diffs it against `index.html`; `--write` rewrites it (then re-lock with `check_pyfa_core.mjs --update`). Re-run after a pyfa/SDE update. |
| `gen_hull_damage_table.py` | Regenerates `SHIP_DAMAGE_MOD_EFFECTS` (PYFA CORE `hull-damage`): every hull/subsystem handler on weapon, charge, drone and fighter damage/RoF with exact filters (every charge x weapon pairing, LESSON #22), plus `kind 'spool'` rows (LESSON #62), and `FIGHTER_ABILITY_EFFECTS` (v2026.10.14.4), asserting every damaging default fighter ability is modeled. Diffs; `--write` embeds. Re-run after a pyfa/SDE update. |
| `pyfa_fit_oracle.py` | **Runs pyfa's own handlers on a whole fit** (hull, modules with charges and states, All 5 skills, modes; `implants=` / `boosters=` (side effects off), `drones=[(type, amountActive)]`, `fighters=[(type, amount)]`), with a hand port of `__calculateValue`, e.g. `OracleFit('Paladin', [('Bastion Module I','active')]).calculate().ship.get('armorEmDamageResonance')`. The resistance reference since v2026.10.14.5. Not modelled: projected/command effects. `Attrs.afflictions` and `Attrs.extended(...)` (a port of `getExtended`) serve `check_projected.py`. `fit.oracleGaps` must be empty (LESSON #27). |
| `gen_resist_table.py` | Regenerates the PYFA CORE `resist-calc` tables (`RESIST_EFFECTS` with operation and stacking group, `RESIST_SKILL_MODULE_ROWS`, `RESIST_ATTRS`, `MODE_ITEMS`) from every hull/module/charge/mode handler on resonances. Diffs; `--write` embeds. Reports skipped carriers. |
| `gen_mode_table.py` | Regenerates the PYFA CORE `modes` table `MODE_EFFECT_ROWS`: every effect of every ship mode (Tactical Destroyers incl. the Skua, the Anhinga) through pyfa's handlers, with value, stacking group and exact filter; asserts each penalized row is alone in its group. Resonances are in `RESIST_EFFECTS`. Diffs; `--write` embeds. |
| `gen_speed_table.py` | Regenerates the PYFA CORE `speed-calc` tables (`SPEED_EFFECTS`, `SPEED_SKILL_ROWS`, `SPEED_ATTRS`, `SPEED_PROP_EFFECTS`, `SPEED_CLOAK_EFFECTS`). Fails if pyfa's Effect6730/6731 source changes (`speed_prop_effects.sha256`; re-check `pyfaPropBoost`, then `--record-prop-source`). Diffs; `--write` embeds; `--verbose` lists rows and handler errors (LESSON #28). |
| `gen_cyno_table.py` | v2026.11.02.2: `CYNO_FIT`, which hulls each cynosural field generator fits (regular, covert, industrial), from the SDE's canFitShipGroupNN / canFitShipTypeN, for the scan rail's Cyno Capable role and tag. In the update chain. |
| `gen_ewar_table.py` | Regenerates the PYFA CORE `ewar-calc` tables (v2026.10.14.11): `EWAR_EFFECTS` (handlers on an EWAR module's range, falloff, strength or neut/nos amount; scripts as `'self'` rows), `EWAR_SKILL_ROWS`, `EWAR_ATTRS`, `EWAR_GROUPS`.
