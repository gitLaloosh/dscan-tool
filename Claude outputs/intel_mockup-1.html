What your logs showed

  • The format is as expected: UTF-16 text; a header with the channel name, the listener and the session start; then [ yyyy.mm.dd hh:mm:ss ] Pilot > message lines in EVE time. One file per channel per session, named Channel_date_time_characterID.txt, so the page can tell your characters apart by the ID in the name.
  • EVE writes promptly: the file's last change matched its last line within about a second, so the feed can be about as fresh as the 2-second read.
  • Your system: the Local log has "Channel changed to Local : <system>" on every jump, as hoped.
  • Logs can be in two places when OneDrive has moved Documents: an old folder stops getting new files. The page will name the folder and how fresh its newest log is, so a stale folder is obvious.
  • Reports aren't tidy, and recognition has to cope with what real people type: mostly "SYSTEM pilot names ship" with clr / nv / +N, but also a * after linked names (when a system or pilot is dragged into chat), shortened systems ("C-J" for a full name), "Pilot (Ship) jumped A from B", lower-case ship names, and Chinese ship names. A word the page can't place is left as plain text, never guessed into a pilot or a system; the raw line is always shown under it.
  • Nothing from your logs goes into the repository or the mockups; the page checks use made-up logs written the same way.

Jumps that stay in sync with EVE

  • From the game itself. Your EVE client carries the stargate list it uses (jumps.static in its resource files): 6,989 gate connections between 5,268 systems, client build 3654997. I read it from C:\CCP\EVE (read only) and checked it against ESI: 1DQ1-A's 4 gates and Jita's 7 match exactly. System names come from ESI (a handful of requests when the table is built). About 100 KB in the page.
  • The page carries the build it came from. When Intel starts, it asks ESI which build Tranquility runs (ESI says 3654997 today, the same number). If EVE has been patched since, the card says so in its line ("EVE patched since the jump table was checked") rather than going quietly out of date.
  • A new step in the update-check chain compares the table with your client's current gate list (by its fingerprint) whenever your computer is linked, and fails if a gate was added or removed. Most patches don't touch gates; then only the build number moves.
  • Chinese (and other language) ship names come from the item data the chain already checks, which has every ship's name in each language.
  • One limit to know: the table knows stargates only. Ansiblex jump bridges are player structures and aren't in CCP's data, and wormholes (Thera, Turnur, ...) change all the time, so "3 jumps" means 3 gate jumps. A list of your own bridges could come later.
